# ADR-0033: プロジェクトを単位に、読み書きできる人を決める

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した。招待、メンバーと公開範囲の変更、権限がなくなった人の接続の扱いは [ADR-0034](0034-invites-and-members.md) で追加)
- 日付: 2026-11-13
- 関連: [ADR-0009](0009-auth-and-access.md)(認証の方針)、[ADR-0032](0032-login-and-sessions.md)(ログイン)、[ADR-0017](0017-page-storage-and-api.md)(ページのAPI。公開環境で止めていた仕組みを、ここで置き換える)、[ADR-0024](0024-page-identity-and-project-index.md)(台帳)

## 状況

ページは、プロジェクトが1つだけ(`default`)という前提で保存していた。ログインの仕組みがなかったので、ページのAPIは、公開環境では丸ごと止めていた(`PAGE_API`)。ログインができるようになったので(ADR-0032)、プロジェクトを作り、メンバーだけが読み書きできるようにする(US-12)。

## 決定

### プロジェクトとメンバー

- プロジェクト(`projects`)とメンバー(`members`)を、D1 に持つ。
- プロジェクトは、変わらないID(乱数)と、名前を持つ。名前は、URLの最初の部分になる(`/名前/ページ`)。小文字の英数字とハイフンで、2文字から40文字まで。大文字は、小文字にそろえる。アプリが使うパス(`api`、`settings`、`invite` など)は、名前にできない。
- Durable Object の名前には、プロジェクトのIDを使う(台帳は `ID`、ページは `ID/ページのID`)。あとで名前を変えられるようにしても、保存先は変わらない。
- 役割は、`admin`(設定とメンバーを変えられる)と `member`。作った人が `admin` になる。
- 公開範囲は、`private`(メンバーだけが読める)と `public`(誰でも読める。書けるのはメンバーだけ)。既定は `private`。
- してよいことは、純粋関数 `allows(役割, 公開範囲, 操作)` で決める(`@amime/shared`)。

| 操作                   | admin | member | メンバーでない人(公開) | メンバーでない人(非公開) |
| ---------------------- | ----- | ------ | ---------------------- | ------------------------ |
| 読む                   | ○     | ○      | ○                      | ×                        |
| 書く                   | ○     | ○      | ×                      | ×                        |
| 設定とメンバーを変える | ○     | ×      | ×                      | ×                        |

### API

- `GET /api/projects`: 参加しているプロジェクトと、新しく作れるかどうか。
- `POST /api/projects`: プロジェクトを作る。
- `GET /api/projects/:project`: プロジェクトと、見ている人の役割。
- ページのAPIは、プロジェクトの下に移す(`/api/projects/:project/pages/...`)。
- **読めない人には、ないものとして応える(404 `unknown-project`)。** ないプロジェクトと、見る権限のないプロジェクトを、応答で区別しない(プロジェクトがあることを、知らせない)。
- 読めるが書けない人(公開のプロジェクトを見ている、メンバーでない人)の、読む以外の要求は、403 `read-only` で断る。
- 書けない人が、まだないページを名前で開いても、台帳にページを増やさない(404 `unknown-page`)。
- 書けない人の WebSocket は、読むだけの接続として受け付ける。他の人の変更は届くが、その人のカーソルは、他の人に配らない。印は Worker が付け、要求に付いてきたものは使わない。
- **`PAGE_API` の設定をやめる。** 公開環境でも、権限のある人は、ページを読み書きできる。権限は、要求のたびに D1 で確かめる。

### プロジェクトを作れる人

- 作れる人を、設定(`PROJECT_CREATORS`)で制限する(ADR-0009)。メールアドレスをカンマで並べる。`*` なら、ログインしていれば誰でも作れる。
- 公開環境では、シークレットで渡す。設定がなければ、誰も作れない。手元での開発と自動テストでは、誰でも作れる。

### 画面

- URLは、`/`(参加しているプロジェクトの一覧)、`/プロジェクト/`(ページの一覧)、`/プロジェクト/ページ`。
- プロジェクトのトップは、末尾に `/` を付けたURLにそろえる。ページへのリンクは、同じ階層を指す相対パス(`./ページ`)なので、`/` がないと、プロジェクトの外を指す。
- プロジェクトを読めることを確かめてから、中身(一覧、ページ)を読み込む。
- メンバーでない人には、読むだけの表示にする。入力を受け取る欄を置かず、ページの操作(固定、削除)と、新しいページを作る欄を出さない。
- ログインしていない人のトップには、案内と、保存されない試し書きのページへのリンクを出す。

## 理由(ユーザーストーリーから)

- **US-12**: 「プロジェクトを作成できる」「公開か非公開にできる」「メンバーでない人は、非公開プロジェクトのページもAPIも見られない」。
- 招待制のチームで使う(ADR-0009)。知らない人に、プロジェクトがあることも知らせない。

## 検討した他の案

- **権限を、Durable Object の中で確かめる**: ページごと、台帳ごとに確かめる処理が散らばる。Worker の入口で1回確かめれば、Durable Object は、確かめ済みの要求だけを受け取れる。
- **見る権限がないときに 403 を返す**: 名前を当てれば、プロジェクトがあることが分かる。
- **プロジェクトの名前を、Durable Object の名前に使う**: 名前を変えると、保存先が変わる。
- **プロジェクトのメンバーを、台帳(ProjectDO)に持つ**: 「自分が参加しているプロジェクト」を引くには、すべての台帳を調べることになる。

## わかっている制約

- これまで手元で書いたページ(プロジェクト `default`)は、引き継がない(公開環境には、まだデータがない)。
- プロジェクトの名前、公開範囲、メンバーを変える画面と、招待は、次の変更で作る。それまで、メンバーは、作った人だけ。
- つないだままの WebSocket は、権限がなくなっても、切れるまで変更を受け取る(メンバーを外す操作は、まだない。外せるようにするときに、あわせて直す)。
- 書いている途中で権限がなくなると、画面は、保存を再試行し続ける。
- プロジェクトを消す操作は、まだない。
- 権限を確かめるために、要求のたびに D1 を2回引く(ログインの状態と、プロジェクト)。
