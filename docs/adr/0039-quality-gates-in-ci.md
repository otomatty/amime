# ADR-0039: CI に、ワークフロー・依存・大きさの検査と、まとめのジョブを足す

- 状態: 採用
- 日付: 2026-11-15
- 関連: [ADR-0008](0008-tdd-and-ci.md)(テスト先行と CI)、[ADR-0037](0037-ci-and-deploy-workflows.md)(CI と Deploy)

## 状況

`main` に入った変更は、検査を通れば、そのまま本番へ出る(ADR-0037)。依頼者から、本番へ出す前に、CI をもっと充実させて、品質を担保したいという依頼があった。

いまの CI(ADR-0008)は、コード(lint、型、未使用コード、テスト先行、カバレッジ、Workers ランタイムのテスト、ビルド、Chromium での E2E)を見ている。次のものは、見ていない。

- **ワークフローそのもの**: Deploy のワークフローは、`main` に入るまで一度も動かない。書き間違い(式、ジョブの依存、`run` の中のシェル)が、本番へ出すときに初めて分かる。
- **依存の脆弱性**: Dependabot は、更新のPRを出すだけで、脆弱性のある版が入ったままでも、検査は通る。
- **配信する大きさ**: 依存を1つ足すだけで、画面のJSが倍になることがある。誰も気付かないまま、スマートフォンでの読み込みが遅くなる。
- **失敗したときの手がかり**: CI の E2E が落ちても、画面の記録(trace)が残らず、手元で再現できないと、原因が分からない。
- **必須にする検査の数**: ブランチ保護で、5つの検査を名前で必須にしている。検査を足したり名前を変えたりするたびに、設定を直す必要がある。

## 決定

`ci.yml` に、次を足す。PRでも、Deploy の中の検査(ADR-0037)でも動く。

| 追加するもの             | どこで       | 内容                                                                                                    |
| ------------------------ | ------------ | ------------------------------------------------------------------------------------------------------- |
| ワークフローの記述       | 規約         | [actionlint](https://github.com/rhysd/actionlint)(版を固定した Docker イメージ)。中で shellcheck も動く |
| 依存の脆弱性             | 規約         | `pnpm audit --prod --audit-level high`。本番で使う依存に、high 以上の既知の脆弱性があれば落とす         |
| 配信するファイルの大きさ | ビルド       | `pnpm check:size`。画面のJS・CSS、Worker の gzip 後の大きさが、上限以下か。結果はジョブの概要に表で出す |
| 失敗したときの記録       | E2E          | 失敗したら、Playwright の報告と trace を、成果物として7日間残す                                         |
| すべての検査             | 新しいジョブ | 5つの検査が、すべて `success` か。ブランチ保護では、これだけを必須にする                                |

大きさの上限は、いまの大きさに4割ほどの余裕を持たせた値にする(`scripts/check-size.ts`)。

| 対象      | いま(2026-11-15) | 上限    |
| --------- | ---------------- | ------- |
| 画面のJS  | 96.9 KiB         | 140 KiB |
| 画面のCSS | 4.2 KiB          | 12 KiB  |
| Worker    | 68.6 KiB         | 256 KiB |

上限を上げるのは構わないが、理由をPRに書く(規約)。対象のファイルが1つも見つからないときも、失敗にする(ビルドの出力の場所が変わって、検査が空振りするのを防ぐ)。

## 理由

- actionlint は、`needs` の書き間違い、存在しない出力の参照、シェルの引用の漏れを、動かす前に見つける。Deploy のように、本番の権限で、まれにしか動かないワークフローほど効く。
- 脆弱性の検査を本番の依存に限るのは、開発にだけ使う道具の脆弱性で、関係のないPRが一斉に落ちるのを避けるため。開発用の依存は、Dependabot の通知で扱う。
- 大きさは、計る仕組みがないと、増えたことに気付けない。上限を、いまより十分大きくしておけば、ふつうの機能追加では落ちず、大きな依存を足したときだけ止まる。
- まとめのジョブを1つ必須にすれば、このあと検査を増やしても(E2E のブラウザを増やすなど)、ブランチ保護を変えずに済む。

## 他の案

- **actionlint を、手元の開発環境にも入れる**: 入れようとしたが、この開発環境では、外からのバイナリの取得ができなかった。CI だけで動かす。
- **CodeQL、依存の差分の検査(dependency-review)**: 非公開のリポジトリでは、GitHub の有料の機能(Advanced Security)が要る。費用がかかるので、入れない。公開するときに、改めて検討する。
- **大きさを、前のコミットとの差で見る**: 増えた量は分かるが、少しずつ増えるのは止められない。上限で見る。

## 結果

- PRごとの検査の時間は、ほとんど変わらない(規約のジョブに、30秒ほど増える)。
- 新しい脆弱性が公表されると、関係のないPRも落ちることがある。そのときは、先に依存を上げる。
- ブランチ保護は、`docs/deploy.md` の 1 に書いたとおり、`すべての検査` だけを必須にする。
- actionlint は、手元では動かせていない。PR の CI で、初めて動く。
