# ADR-0020: 未送信の変更を端末内に残す

- 状態: 採用
- 日付: 2026-11-13
- 関連: [ADR-0006](0006-sync-model.md)、[ADR-0016](0016-changes-and-line-ids.md)、[ADR-0017](0017-page-storage-and-api.md)(「タブを閉じると、まだ送っていない変更は失われる」という制約を、このADRで解消する)

## 状況

通信が切れているあいだに書いた内容は、タブを開いているかぎり、通信が戻れば送られる(ADR-0017)。しかし、送れないままタブを閉じると失われる。ブラウザが落ちた場合や、確認を見落として閉じた場合も同じである。US-05 は「通信が切れたりタブを閉じたりしても、書いた内容が残っていてほしい」と求めている。

## 決定

### 何を、どこに残すか

- 残すのは、**まだサーバーに入っていない自分の変更**(確定した文書と画面の文書の差分。送信中の変更を含む)。文書の全体ではない。
- 残す先は、ブラウザの `localStorage`。記録は、ページと端末(タブ)の組ごとに1つ持つ。
- 編集のたびに、その場で書き込む。保存が終わって未送信の変更がなくなったら、記録を消す。
- まだないページに表示している仮のタイトルは、残さない(開いただけではページを作らないのと同じ。ADR-0017)。

### 次に開いたとき

1. ページを読み込む。
2. そのページについて残っている記録を、**すべて引き取る**(このタブの記録に移してから、元の記録を消す)。
3. 読み込んだページに、引き取った変更を古い順に載せる。規則は、ふだんの適用と同じ(ADR-0016)。対象の行がなくなっている変更は、その変更だけを捨てる。既にサーバーに入っていた変更は、もう一度適用しても何も起こさない。
4. 載せた結果が読み込んだページと違えば、それを画面に表示し、編集を待たずに保存する。「前回、送信できなかった変更を復元しました」と表示する。

### 細かい扱い

| 場面                                                                 | 挙動                                                                                           | 理由                                                                                                                                   |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 閉じているあいだに、他の人が別の行を書いていた                       | 両方が残る                                                                                     | 行IDを対象にした変更なので、互いに干渉しない                                                                                           |
| 閉じているあいだに、他の人が同じ行を書き換えていた                   | 復元した自分の変更が上書きする                                                                 | ふだんの「あとからサーバーに届いたほうが残る」(ADR-0016)と同じ規則。通信が切れたままタブを開いていた場合と、結果が変わらないようにする |
| 同じページを開いている別のタブがあり、そのタブにも未送信の変更がある | 新しく開いたタブが、その変更も引き取って送る。元のタブも自分で送るが、同じ変更は二重に効かない | 記録だけを見ても、そのタブが閉じているかどうかは分からない。引き取っておけば、どちらが先に閉じても失われない                           |
| 30日より古い記録                                                     | 復元せずに消す                                                                                 | 古い変更で、新しい内容を上書きする危険のほうが大きい                                                                                   |
| 読めない記録(壊れている、形が違う)                                   | 復元せずに消す                                                                                 |                                                                                                                                        |
| `localStorage` が使えない、容量がいっぱい                            | 残さずに続ける。保存そのものは、これまでどおり動く                                             | 端末内に残すのは、失わないための予備である                                                                                             |

### ページを離れる前の確認は、出し続ける

未送信の変更があるあいだは、これまでどおり、ページを離れる前にブラウザの確認を出す。端末内に残っていても、サーバーには入っていない。そのままでは他の人には見えず、別の端末からも続きを書けないためである。

## 理由(ユーザーストーリーから)

- **US-05**「通信が切れたりタブを閉じたりしても、書いた内容が残っていてほしい」: タブを閉じる、ブラウザが落ちる、端末の電源が切れる、のどれでも、最後の編集までが端末内に残る。編集のたびにその場で書き込むので、閉じる瞬間に書き込む必要がない。
- **US-04**「別々の行への同時編集は、どちらも失われない」: 復元は、文書を置き換えるのではなく、変更を載せ直す。閉じているあいだの他の人の変更は残る。

## 検討した他の案

| 案                                                       | 採用しなかった理由                                                                                                                                      |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IndexedDB に残す                                         | 書き込みが非同期なので、タブを閉じる直前の編集が書き終わる保証がない。`localStorage` はその場で書き終わる。容量は小さいが、残すのは差分だけなので足りる |
| 文書の全体を残す                                         | 次に開いたときに、他の人の変更を巻き戻してしまう。差分なら、新しい文書に載せ直せる                                                                      |
| 閉じるとき(`pagehide`)にだけ書き込む                     | ブラウザが落ちたときや、モバイルで強制的に終了されたときに書き込めない                                                                                  |
| ページごとに記録を1つだけ持つ                            | 同じページを2つのタブで開いていると、互いの記録を上書きして、片方の変更を失う                                                                           |
| 残っている記録を、どのページを開いたときでもまとめて送る | 画面に出ていないページを裏で書き換えることになる。P3 でページの一覧ができたら、未送信の変更があるページをそこで知らせる                                 |

## わかっている制約

- 復元されるのは、**同じブラウザで、そのページをもう一度開いたとき**だけである。開かないかぎり、変更は端末内に残ったままで、他の人には届かない。
- 同じ行を他の人が書き換えていた場合、復元した自分の変更が上書きする(上の表のとおり)。行の中の統合は、同じ行の同時編集(ADR-0016)と合わせて決める。
- 取り消しの履歴は残らない。復元した変更は、取り消せない(ADR-0019)。
- 未送信の内容が、送り終わるまで(最長30日)ブラウザに平文で残る。共用の端末では、他の利用者が同じブラウザで読める。ログイン(P4)を入れるときに、ログアウトで消すなどの扱いを決める。
- `localStorage` の容量(ブラウザごとに数MB程度)を超える量の未送信の変更は、残せない。
