# ADR-0019: 取り消しは、自分の編集だけを打ち消す

- 状態: 採用(他の人も書き換えた行の取り消しは [ADR-0022](0022-merge-within-a-line.md) で置き換え)
- 日付: 2026-11-12
- 関連: [ADR-0014](0014-selection-clipboard-undo.md)(取り消しの方式を、このADRで置き換える)、[ADR-0016](0016-changes-and-line-ids.md)、[ADR-0018](0018-realtime-delivery.md)

## 状況

これまでの取り消しは、文書全体の状態を覚えておき、取り消すとその状態に巻き戻す方式だった(ADR-0014)。共同編集では、この方式は使えない。巻き戻すと、そのあいだに他の人が書いた内容まで消えるためである。そこで、他の人の変更が届くたびに履歴を捨てていた(ADR-0017、ADR-0018)。複数人で同時に書いていると、取り消しがほとんど使えなかった。

ADR-0014 は、P2 で「自分が行った変更を打ち消す変更を作る」方式に置き換えると決めていた。

## 決定

### 履歴は「自分が行った編集」を覚える

- 取り消しの1単位は、自分の編集を、行IDを対象にした変更(ADR-0016)として覚える。編集そのもの(やり直すときに使う)と、それを打ち消す変更(取り消すときに使う)の両方を持つ。
- 取り消しは、いまの文書に「打ち消す変更」を適用する。文書を過去の状態に戻すのではない。他の人の変更は、対象になっていないので残る。
- 取り消した結果は、ふつうの編集と同じように保存され、他の人に配信される。取り消しのための特別な経路はない。

### 打ち消すときの規則

| 自分が行った編集     | 取り消すと                 | 他の人が先に変えていた場合                                                 |
| -------------------- | -------------------------- | -------------------------------------------------------------------------- |
| 行の本文を書き換えた | 書き換える前の本文に戻す   | その行を他の人がさらに書き換えていたら、戻さない。消していたら、何もしない |
| 行を足した           | その行を消す               | その行を他の人が書き換えていたら、消さない                                 |
| 行を消した           | 同じ行IDで、元の位置に戻す | 前後の行がなくなっていたら、近い位置に戻す(ADR-0016 の位置の規則)          |
| 行を動かした         | 元の位置に戻す             | 行がなくなっていたら、何もしない                                           |

「他の人が書き換えていたら」は、行の本文が、自分が最後に書き込んだ本文と違うかどうかで判断する。違っていれば、その行には他の人の変更が入っているので、手を付けない。**取り消しで、他の人の書いた内容を消すことはない。**

- 1つの編集のうち、打ち消せる部分だけを打ち消す(改行を取り消すとき、足した行を他の人が書き換えていたら、その行は残して、分けた行の本文だけを戻す)。
- 打ち消せる部分が1つもない編集は飛ばして、その前の編集を取り消す。キーを押しても何も起きない、ということを避ける。
- やり直しも同じ規則で行う。取り消したあとに他の人が書き換えた行には、やり直さない。
- 取り消したときに、やり直しのために覚えるのは「その取り消しで実際に変わった分」である(やり直したときも同じ)。一部しか取り消せなかった編集をやり直しても、取り消していない部分(他の人が消した行など)は変わらない。

### カーソルと選択

- 編集の前後のカーソルと選択は、行番号ではなく行IDで覚える。取り消すと、他の人が行を足したり消したりしていても、同じ行に戻る。
- 戻る先の行がなくなっていたら、カーソルはいまの位置(範囲に収める)に置き、選択はやめる。

### 他の人の変更が届いたとき

- 履歴は消さない。
- 続けて打っていた入力のまとまり(ADR-0014 の「1秒以内の入力は1回の取り消しにまとめる」)は、そこで区切る。区切らないと、まとまりの始まりの文書と見比べたときに、他の人の変更まで自分の編集に含めてしまう。

### 置き場所

- 変更としての記録と打ち消し(`recordEdit`、`revertEdit`、`reapplyEdit`)は `@amime/sync` に置く。
- 履歴(`@amime/editor-core` の `history.ts`)が、行IDつきの文書を持つ。そのため `editor-core` は `sync` に依存する。`applyEdit`、`undo`、`redo` の呼び出し方は変わらない。最初の文書の渡し方(`createHistory`)は行IDつきになり、他の人の変更を取り込む `replaceLines` が加わった。

## 理由(ユーザーストーリーから)

- **US-04**「別々の行への同時編集は、どちらも失われない」: 取り消しは編集の一種である。取り消しで他の人の行が消えたり、内容が巻き戻ったりすれば、この基準を破る。
- **US-05**(書いたものを失わない): 誤って消したものを取り消しで戻せることは、共同編集の最中でも同じように使えなければならない。
- 消した行を取り消しで戻すと、同じ行IDで戻る。他の人から見ても「同じ行が戻った」ことになり、行ごとの履歴(US-06)も途切れない。

## 検討した他の案

| 案                                                                                       | 採用しなかった理由                                                                                      |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 文書の状態を覚える方式のまま、他の人の変更が届くたびに、覚えている状態をすべて書き換える | 届くたびに「履歴の数 × 行数」の計算になる。打ち消す変更を覚える方式なら、届いたときには何もしなくてよい |
| 条件を付けずに、書き換える前の本文へ戻す                                                 | 自分が書き換えたあとで他の人がその行に書いた内容を、取り消しが消してしまう                              |
| 取り消せない編集で止まる(飛ばさない)                                                     | 取り消しのキーを押しても何も起きないことがあり、壊れたように見える                                      |
| サーバーの履歴を使って取り消す                                                           | 取り消しは手元の操作として、通信なしですぐ効く必要がある。未送信の編集も取り消せなければならない        |

## これで解消した制約

- 他の人の変更が届くたびに、取り消しの履歴が消える(ADR-0017、ADR-0018)。
- 削除を取り消して戻した行に、新しい行IDが付く(ADR-0016)。

## わかっている制約

- 判断は行単位である。自分が書き換えた行に、他の人が1文字でも書き足すと、その行への自分の編集は取り消せなくなる。行の中の文字単位の扱いは、同じ行の同時編集(ADR-0016)と合わせて決める。
- 行を動かした編集の取り消しは、そのあとで他の人が同じ行を動かしていても、自分が動かす前の位置へ戻す。
- 履歴は端末(タブ)の中にだけある。ページを開き直すと、取り消せない。覚えておく単位は 500 まで(ADR-0014 のまま)。
