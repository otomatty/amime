# ADR-0026: ページを一覧の先頭に固定する。ページを削除する

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した)
- 日付: 2026-11-13
- 関連: [ADR-0024](0024-page-identity-and-project-index.md)(ページのIDと台帳)、[ADR-0025](0025-page-index-and-list.md)(一覧。「固定と削除は、まだない」を埋める)、[ADR-0009](0009-auth-and-access.md)

## 状況

一覧(ADR-0025)には、いつも先頭に置いておきたいページを固定する方法がなかった(US-09)。
書いたページを消す方法もなかった。試しに作ったページが、一覧に残り続けていた。

## 決定

### 固定

- 固定は、**プロジェクトで共有する**。だれかが固定すると、全員の一覧で先頭に並ぶ。
- 台帳(`ProjectDO`)が、ページごとに固定した時刻を持つ(固定していなければ 0)。
- 一覧は、どの並び順でも、固定したページを先に並べる。固定したページどうしは、あとから固定したものを先にする(同じ時刻に固定しても、あとのものが先)。すでに固定しているページをもう一度固定しても、順は変わらない。
- `PUT /api/pages/:id/pin` に `{ "pinned": true | false }` を送る。台帳にないページなら 404。
- 固定は、ページの画面で切り替える。一覧のカードには、固定していることの印を出す。
- 固定は、ページのIDに付く。名前を変えても、固定は外れない。

### 削除

- 削除は、**元に戻せない**。ごみ箱は持たない。画面は、押しただけでは削除せず、元に戻せないことを伝えて確かめる。
- `DELETE /api/pages/:id` が、次の順に行う。何度呼んでも、結果は同じ(204)。
  1. `PageDO` が、本文・受け取ったコミットの記録・名前の控えを消し、**削除されたことを覚える**。台帳への知らせの予約も取り消す。
  2. 台帳が、ページの行と、そのページからのリンクを消し、**消したページのIDを覚える**。
- 1 のあとで 2 に失敗すると、台帳にだけページが残る。そのページを読もうとしたとき(410 を返すとき)に、台帳からも消す。
- 削除された `PageDO` は、読み込みにもコミットにも「削除された」と答える。APIは 410(`page-deleted`)を返す。
- 開いている端末には、WebSocket で `{ "type": "deleted" }` を送り、接続を閉じる。あとから接続した端末にも、同じことを伝えて閉じる。
- 画面は、削除されたことを表示し、保存と再接続をやめる。まだ送っていなかった変更は、捨てる。書いてあった内容は、画面に残す(写しておける)。削除されたと分かったあとに届いたサーバーの応答では、画面の文書を置き換えない。
- 削除したページのIDは、使い回さない。同じ名前をもう一度開くと、**別のIDの、新しいページ**になる(ADR-0024 のIDの決め方で、消したIDを飛ばす)。
- 削除したページについての知らせが、あとから台帳に届いても、台帳に載せ直さない。
- 削除したページへのリンクは、まだないページへのリンクと同じ扱いになる。他のページの本文は書き換えない。

## 理由(ユーザーストーリーから)

- **US-09**「ページを一覧の先頭に固定できる」: 並び順を変えても見失わないように、どの並び順でも先に並べる。
- **US-04 / US-05**: 削除されたことを覚えておかないと、開いたままの端末や、通信が切れていた端末が、あとから変更を送って、消したページを作り直してしまう。IDを使い回さないのも、同じ理由である(端末に残っている変更は、ページのIDで保存されている)。
- **US-01**「書いたものが失われない」: 削除は、書いたものを失わせるただ1つの操作になる。確かめてから行い、開いていた端末には内容を残す。

## 検討した他の案

| 案                                                 | 採用しなかった理由                                                                                                   |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 固定を、人ごとに持つ                               | 認証(P4)の前は、人を区別できない。チームで「まず読むページ」を揃える用途には、共有のほうが合う                       |
| 固定したページの順を、手で並べ替えられるようにする | 固定するページは少ない。必要になってから足せる                                                                       |
| ごみ箱に移し、あとで戻せるようにする               | 戻したときの名前の重なり、リンクの扱い、消すまでの期間など、決めることが多い。履歴(P6)と合わせて考える               |
| `PageDO` の保存内容をすべて消す(`deleteAll`)       | 削除されたことも忘れる。あとから届いたコミットで、台帳にないページの本文ができてしまう                               |
| 台帳から先に消し、あとで本文を消す                 | 途中で失敗すると、一覧にないのに本文が残る。IDを知っていれば読めてしまい、気づく方法もない                           |
| 削除したページのIDを、同じ名前の新しいページに使う | 端末に残っている、削除前のページへの変更が、新しいページに混ざる                                                     |
| 削除したページへのリンクを、他のページから取り除く | 他の人が書いた本文を、削除のついでに書き換えることになる。まだないページへのリンクとして残すほうが、あとで作り直せる |

## わかっている制約

- 削除できるのは、書き込める人すべてである。認証(P4)が入るまで、ページのAPIは公開環境で無効にしている(ADR-0009)。権限による制限は、P4で考える。
- 削除は元に戻せない。バックアップ(P5)と履歴(P6)が入るまで、消したページを取り戻す方法はない。
- 消したページのIDと、削除された `PageDO` の印は、消えずに残る。ページの作成と削除を非常に多く繰り返すと、台帳の記録が増え続ける。
- 削除された `PageDO` に、通信が切れていた端末が変更を送ってきたとき、その変更は捨てられる。その端末の画面には、削除されたことを表示する。
- 一覧を開いたままの画面には、他の人の固定や削除は、読み込み直すまで反映されない。
- 台帳にあるIDかどうかを確かめずに削除を受け付ける。まだ使われていないIDを指定すると、そのIDが使えなくなる(新しいページは、次の候補のIDで作られる)。
