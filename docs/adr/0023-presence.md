# ADR-0023: 他の人のカーソルと、接続の状態を表示する

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した)
- 日付: 2026-11-13
- 関連: [ADR-0018](0018-realtime-delivery.md)(WebSocket でクライアントから送るメッセージを、このADRで足す)、[ADR-0016](0016-changes-and-line-ids.md)、[ADR-0009](0009-auth-and-access.md)

## 状況

同じページを開いている人の変更は、その場で届く(ADR-0018)。しかし、相手がいまどこを見て、どこに書こうとしているかは分からない。同じ行の同時編集は統合されるようになった(ADR-0022)が、相手がいる場所が見えれば、そもそも同じ場所を同時に触ることを避けられる。

また、WebSocket が切れていても、画面からは分からなかった。切れているあいだは、他の人の変更が届かない。

## 決定

### カーソルの位置を、WebSocket で配る

- カーソルの位置は、**行IDと、行の中の位置**で表す(行番号ではない)。他の人が行を足したり消したりしても、同じ行を指し続ける。
- 編集欄は、自分のカーソルが動くたびに、位置をサーバーへ送る。編集欄にフォーカスがないあいだは「カーソルを出していない」と送る。
  - 続けて動かしているあいだは、0.1秒に1回まで、最後の位置だけを送る。同じ位置は、続けて送らない。
- サーバー(`PageDO`)は、受け取った位置を、同じページに接続している他の端末へ配る。送った本人には配らない。
- カーソルの位置は、**保存しない**。接続に添えて覚えておく(WebSocket の attachment。休止しても残り、接続が閉じれば消える)。
- あとから接続した端末には、接続した直後に、いまいる端末のカーソルをまとめて送る。
- 接続が閉じたら、その端末がいなくなったことを、他の端末に知らせる。同じ端末がつなぎ直した直後で、新しい接続が残っているときは、知らせない。

メッセージは、次のとおり。

| 向き            | メッセージ                                             | 意味                                          |
| --------------- | ------------------------------------------------------ | --------------------------------------------- |
| 端末 → サーバー | `{ type: "cursor", cursor: { line, column } \| null }` | 自分のカーソルの位置。`null` は、出していない |
| サーバー → 端末 | `{ type: "cursor", client, cursor }`                   | 他の端末のカーソルの位置                      |
| サーバー → 端末 | `{ type: "leave", client }`                            | 他の端末が接続を閉じた                        |

- 端末が送れるのは、`ping`(ADR-0018)と、このカーソルの位置だけ。形の違うメッセージを送ってきた接続は、これまでどおり閉じる。
- 変更の保存は、これまでどおり HTTP で行う。カーソルの位置は、失われても困らず、順序も問わないので、WebSocket で送る。

### 画面に出す

- 他の人のカーソルは、その行のその位置に、色のついた縦線で出す。色は、端末の識別子から決める(同じ人は、いつも同じ色)。
- 位置は、**送った人の画面での位置**である。受け取った側の本文とは、変更が届くまでのあいだ、少しずれることがある。ずれているときは、近い位置に寄せる(行の本文より後ろなら行末、隠している記法の中なら、その記法のあった場所)。
- この文書にない行を指すカーソルは、出さない。
- 接続が切れたら、他の人のカーソルをすべて消す。切れているあいだの動きは分からない。つなぎ直すと、サーバーがいまの位置を送ってくる。

### 接続の状態

- 保存の状態の下に、接続の状態を出す。「接続しています…」「オンライン」「オフライン(つなぎ直しています…)」の3つ。
- 保存の状態とは、別に出す。切れていても、書いたものは端末内に残り(ADR-0020)、つながったら送られる。接続の状態が知らせるのは、「いま、他の人の変更がその場で届くかどうか」である。

## 理由(ユーザーストーリーから)

- **US-04**「他の人のカーソル位置と名前が見える」: 位置は、このADRで見えるようになる。**名前は、まだ出せない。** だれが開いているかを知る方法(ログイン)が P4 までないためである。それまでは、色で人を見分ける。
- **US-05**「未保存の変更があることが、画面で分かる」: 保存の状態に加えて、他の人の変更が届かない状態も、画面で分かるようにする。

## 検討した他の案

| 案                                                 | 採用しなかった理由                                                                               |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| カーソルの位置を、行番号と位置で送る               | 他の人が上の行を足しただけで、指す行がずれる                                                     |
| カーソルの位置も HTTP で送る                       | 動くたびに要求が発生する。保存と違って、失われても困らないので、開いたままの接続で送るほうが軽い |
| カーソルの位置を、ページと一緒に保存する           | 接続が閉じれば意味がなくなる情報である。保存すると、書き込みが増え、消し忘れた位置が残る         |
| 受け取った位置を、届いた変更に合わせて動かし続ける | 相手は、動くたびに新しい位置を送ってくる。ずれているのは、変更が届くまでの短いあいだだけである   |
| 選択している範囲も見せる                           | まず、どこにいるかが分かれば足りる。必要になったら足す                                           |

## わかっている制約

- 名前は出ない。色だけで人を見分ける。色は8色で、人が多いと同じ色になる。ログイン(P4)ができたら、名前を添える。
- 「人」ではなく「端末(タブ)」ごとに出る。同じ人が2つのタブで開いていると、カーソルは2つ出る。
- 相手が日本語入力で変換している途中の文字は、見えない(確定して保存されるまで届かない)。
- カーソルが動くたびに、休止している `PageDO` が起きる。送る回数は端末の側で抑えている(0.1秒に1回まで)が、サーバーの側では数を制限していない。ページのAPIは、認証が入るまで公開環境では無効である(ADR-0009)。認証を入れるときに、端末ごとの制限をあわせて決める。
- 画面を読み上げる道具には、他の人のカーソルを伝えていない(Issue #3)。
