# ADR-0042: 名前から引けなくなった、端末内の未送信の変更へ案内する

- 状態: 採用
- 日付: 2026-11-16
- 関連: [ADR-0020](0020-pending-changes-on-device.md)(未送信の変更を端末内に残す)、[ADR-0024](0024-page-identity-and-project-index.md)(ページをIDで識別する。「わかっている制約」)、[Issue #18](https://github.com/otomatty/tsuzuri/issues/18)

## 状況

未送信の変更は、ページIDごとに端末内に残す(ADR-0020、ADR-0024)。ページを開くと、URLの名前から台帳でIDを引き、そのIDの記録を復元して送る。

次の2つの場合は、名前から引いたIDが、記録を残したページのIDと違うので、復元されない(ADR-0024「わかっている制約」、Issue #18)。

1. **閉じているあいだに、他の人がページの名前を変えた。** 前の名前で開くと、まだないページ(別のID)が開く。
2. **通信できないまま書いた新しいページの名前が、他のページのものになった。** 他の人が、別のページの1行目をその名前に変えた。または、開いただけのページが1日たって台帳から消えたあとで、他の人が同じ名前のページを作った。その名前で開くと、他の人のページが開く。

変更は、端末内に30日のあいだ残っている。しかし、画面からは辿れない。Tsuzuri は本番で使われ始めた。書いたものが、利用者から見えなくなるのは、データを失うのと同じである(US-05)。

## 決定

### 記録に、どのページのものかを添える

- 端末内の記録に、**プロジェクト、ページID、ページの名前**を添える(`PendingRecord.page`)。
- 名前は、ページを開いたときの名前から始め、サーバーが名前の変更を知らせてきたら直す(`retitle`)。記録を残した時刻は変えない。
- この形を入れる前に残した記録には、ない。そのページを開けば、これまでどおり復元する。
- 添えた情報の形が違っても(壊れた、手で書き換えた)、**添えた情報だけを捨てる**。記録ごと受け付けないと、読めない記録として消され、未送信の変更が失われる。

### 2つの場所で案内する

| 場所                     | 出すもの                                                                                                                                                               |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ページ(名前で開いたとき) | 開いた名前と同じ名前で、別のページIDの記録が残っていれば、「「名前」の名前で書いた、送れていない変更が、この端末に残っています」と案内し、そのページを開くリンクを出す |
| プロジェクトのトップ     | 「この端末に、送れていない変更があるページ」。このプロジェクトの記録を、新しく残した順に、名前と時刻で並べる。メンバーにだけ出す                                       |

- 名前は、ページの名前と同じ規則で比べる(大文字と小文字、空白とアンダースコアの違いは区別しない)。
- 同じページに、タブごとの記録が複数あれば、いちばん新しい記録の名前と時刻にまとめる。
- 名前を変えて書き続けたページは、前の名前では案内しない。
- 判定は `packages/sync` の純粋関数(`pendingPages`、`strayPages`)にする。

### ページを、IDで開けるようにする

- URL は **`/プロジェクト/?page=ページID`**。案内のリンクは、ここを指す。
- 画面は、新しいAPI **`GET /api/projects/:project/pages/:id/info`** で、台帳からいまの名前を引く(`ProjectDO.info`)。台帳になければ 404。
- 台帳にない(1度も保存できなかった)ページは、端末内の記録の名前で開き、残っていた変更を復元して送る。送れば、台帳に載る。名前が重なっていれば、重ならない名前(「名前 (2)」)で載る(ADR-0024)。
- 開いたあとは、URLをページのいまの名前に合わせる(これまでどおり)。ただし、台帳にないページは、台帳が名前を決めて知らせてくるまで、URLを変えない。その名前は別のページのものなので、先に変えると、再読み込みで別のページが開く。
- 台帳にもなく、端末内の記録にもないIDは、「このページは、まだありません」と出す。

## 理由

- 記録に名前を添えれば、名前で開いたときに、同じ名前で書いた別のページの記録を見つけられる(Issue #18 の案)。名前さえ覚えていれば、書いた人は辿れる。
- 名前を忘れていても、プロジェクトのトップの一覧から辿れる(Issue #18 のコメントの案)。名前が変わった、取られた、のどちらでも、同じ一覧で済む。
- 案内するだけで、自動では送らない。名前の重なり方によっては、どのページに入れるべきかを、書いた人が判断したほうがよい。開けば、これまでの復元の手順(ADR-0021、ADR-0022)で送る。
- IDで開く経路は、これまでの「IDでページを読み書きする」仕組み(ADR-0024)を、画面から使えるようにするだけである。台帳にないIDへの書き込みも、もともと受け付けている。

## 他の案

- **名前で開いたときに、別のIDの記録も、そのページに入れて送る**: 別のページの変更を、他の人のページに混ぜてしまう。
- **名前が変わったときに、端末内の記録のキーを付け替える**: 閉じているタブの記録は、付け替えられない(他の人が名前を変えたときは、そもそも知らない)。
- **案内せずに、自動でIDのページへ送る**: 書いた人が、どこに入ったかを知らないままになる。

## 結果

- 端末内の記録が、少し大きくなる(プロジェクト名、ID、名前)。
- 記録の形が変わるので、この変更より前のタブ(古い画面)が残した記録には、ページの情報がない。そのページを名前で開けば、これまでどおり復元する。
- 他のタブで、いま書いているページの記録も、トップの一覧に出る(送れていないのは事実なので、そのままにする)。
- 2人が同じ新しいページを、片方は通信できないまま書いた場合は、台帳に「開いただけ」のページが残っているあいだ(1日)は、同じIDになり、両方の変更が1つのページにまとまる(これまでどおり)。案内は出ない。
- 案内とトップの一覧は、ページを開いたときに1度だけ見る。開いたあとで、別のタブで送り終えても、消えない。
