# ADR-0027: 関連するページを並べ、まだないページへのリンクを区別する

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した)
- 日付: 2026-11-13
- 関連: [ADR-0025](0025-page-index-and-list.md)(台帳のリンク先の表を使う)、[ADR-0024](0024-page-identity-and-project-index.md)

## 状況

ページの中のリンクは、押せば開けるだけだった。いま見ているページに関係するページを見つける方法がなく(US-07)、リンク先のページがあるのかどうかも、開くまで分からなかった。

台帳(`ProjectDO`)は、どのページがどの名前へリンクしているかを持っている(ADR-0025)。これを使う。

## 決定

### ページのつながり

`GET /api/pages/:id/links` が、台帳から次の3つを返す。

- **関連するページ**(`related`): このページがリンクしているページと、このページへリンクしているページ。更新が新しい順に、100件まで。
- **同じリンクを持つページ**(`hops`。2ホップ先): このページのリンク先ごとに、同じ名前へリンクしている他のページをまとめる。
  - リンク先のページがまだなくても、まとめる(同じ言葉を書いたページどうしが、つながる)。
  - 同じリンクを持つページが他になければ、そのリンク先のまとまりは作らない。
  - リンク先のページそのものは、まとまりに入れない(関連するページに出ている)。
  - まとまりの中は更新が新しい順に20件まで。全体で1,000件まで。
- **まだないページへのリンク**(`missing`): このページのリンクのうち、保存されたページがない名前(正規化したもの)。開いただけのページ(ADR-0024)は、まだないページとして扱う。

まだ保存されていないページでも、その名前へリンクしているページは返す。まだないページへのリンクを開いたとき、どこから参照されているかが分かる。

### 画面

- ページの本文の下に、関連するページをカードで並べる(一覧と同じカード)。同じリンクを持つページは、リンク先ごとに見出しを付ける。見出しから、リンク先を開ける。
- 本文の中の、まだないページへのリンクは、見た目で区別する(色を抑え、破線の下線を引く)。開くと、その名前で書き始められる(ADR-0024)。
- つながりは、ページを開いたときと、台帳への反映が済んだと知らされたとき(WebSocket の `page`。ADR-0024)に取り出す。自分が書いたリンクは、書き換えが落ち着いてから(約2秒後)反映される。
- つながりをまだ取り出していないあいだと、取り出せなかったときは、リンクをふつうのリンクとして見せる。ページの読み書きは、つながりを待たない。

### 台帳

- リンク先の表に、**書かれたとおりの名前**を持つ(これまでは、正規化した名前だけ)。まだないページへのリンクのまとまりに、名前を付けるために使う。この変更より前に保存したリンクは、次に反映されるまで、正規化した名前から作った名前(小文字、空白)で見せる。

## 理由(ユーザーストーリーから)

- **US-07**「ページの下に、そのページへリンクしているページと、同じリンクを持つページ(2ホップ先)が並ぶ」「まだ存在しないページへのリンクは、見た目で区別できる。開くとそのタイトルで新しいページを書き始められる」に対応する。
- **US-01**(考えを止めずに書ける): 書いている最中に、リンク先の有無を問い合わせて待たせない。自分のページのつながりは、台帳への反映のあとにだけ変わるので、その知らせを受けて取り出す。

## 検討した他の案

| 案                                                           | 採用しなかった理由                                                                                                     |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| あるページの名前(`existing`)を返し、それ以外をまだないとする | つながりを取り出す前や、書いた直後のリンクが、いったん「まだない」に見える。あるページへのリンクが、ちらつく           |
| リンクを書くたびに、その名前のページがあるかを問い合わせる   | 入力のたびに通信が要る。台帳への反映(約2秒後)を待てば足りる                                                            |
| プロジェクトのすべてのページの名前を、画面に持っておく       | ページが増えると大きくなる。名前の補完(US-07。このあとの変更)で、必要な分だけを取り出す仕組みを作る                    |
| つながりを、ページの本文と一緒に `PageDO` から返す           | `PageDO` は、他のページのことを知らない。台帳に聞く                                                                    |
| 2ホップ先から、関連するページに出ているページを除く          | どのリンクでつながっているかが分からなくなる。まとまりごとに、そのリンクを持つページをすべて見せるほうが、たどりやすい |
| 他のページの変更(ページができた、消えた)を、その場で知らせる | 台帳から、開いているすべてのページへ知らせる仕組みが要る。読み込み直すか、次に反映されたときに追いつけば足りる         |

## わかっている制約

- 他のページが作られたり、消されたり、リンクを書き換えられたりしても、開いている画面のつながりは、その場では変わらない。自分のページが台帳に反映されたときか、読み込み直したときに追いつく。
- 自分が書いたリンクが、まだないページへのリンクだと分かるのは、書き換えが落ち着いてから(約2秒後)である。それまでは、ふつうのリンクに見える。
- 通信が切れているあいだは、つながりは古いままになる。
- リンクが非常に多いページでは、同じリンクを持つページを取り出す問い合わせが重くなる。件数は制限しているが、数えるための読み出しは制限していない。
- 関連するページが100件、まとまりの中が20件を超えると、残りは見られない(検索で探す。このあとの変更)。
- 他のプロジェクトへのリンク(`[/project/page]`)は、つながりに含めない。
