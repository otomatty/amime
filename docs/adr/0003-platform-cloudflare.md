# ADR-0003: Cloudflare 上の構成と使用するサービス

- 状態: 採用
- 日付: 2026-11-11

## 状況

Cloudflare 上で動かすことが前提条件である。招待制のチームが使い、同じページを複数人が同時に編集する。

## 決定

| 役割                         | サービス                                                   | 理由                                                             |
| ---------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------- |
| 配信とAPI                    | Workers + Static Assets(1つの Worker)                      | SPAとAPIを同じオリジンで配信でき、CORSとCookieの扱いが単純になる |
| ページの編集と保存           | Durable Objects(SQLite)、1ページ = 1 `PageDO`              | コミットを1か所で直列化でき、WebSocketを保持できる               |
| プロジェクト内の索引         | Durable Objects(SQLite)、1プロジェクト = 1 `ProjectDO`(P3) | リンクグラフ・検索・更新通知をプロジェクト単位で一貫して扱える   |
| ユーザー・プロジェクト・権限 | D1(P4)                                                     | プロジェクトをまたぐ関係データで、SQLで問い合わせたい            |
| 画像・ファイル               | R2(P5)                                                     | 大きなバイナリの保存先                                           |

- CLIと設定は `cf` と `cloudflare.config.ts` を使う。Wrangler の設定ファイルは置かない。
- クライアントは Vite + React のSPA、APIは Hono。
- 無料プランの制限内で動く設計にする。有料プランが前提になる機能を入れるときはADRを書く。

## 理由(ユーザーストーリーから)

- **US-04 同時編集**: 同じページへの変更を全員に同じ順序で届ける必要がある。Durable Object は1インスタンスが単一スレッドで動くため、ロックや外部のキューなしで順序を決められる。
- **US-01 すぐ書ける**: エディタはクライアントだけで完結し、ページ遷移も通信を待たずに行いたい。SSRで得るものが少ないため、SPAにする。
- **US-07 つながる**: 関連ページと2ホップリンクはプロジェクト全体のリンク情報を必要とする。ページごとの Durable Object に分散させたままでは問い合わせできないので、プロジェクト単位の索引を別に持つ。

## 検討した他の案

- **プロジェクトごとに1つの Durable Object にすべてを持たせる**: 実装は単純で、ページをまたぐ更新も1トランザクションで済む。ただし、プロジェクト内の全員のキー入力が1スレッドに集中する。編集の経路(`PageDO`)と索引の経路(`ProjectDO`)を分けるほうが、人数が増えても編集の応答が落ちない。
- **D1 だけで保存する**: 同時編集の順序付けを自前で実装する必要があり、WebSocketの置き場所もない。
- **SSRフレームワーク(React Router など)**: 公開ページのOGPには有利だが、エディタには不要。OGPは Worker でメタタグを差し込めば足りる。

## リスク

- `cf` CLI、`@cloudflare/vite-plugin` 2.x、`cloudflare.config.ts` はベータ版(2026-11-11 時点で `cf` 1.0.0-beta.29)。設定の形が変わる可能性がある。
  - 対策: 依存の更新は Dependabot のPRで受け、CIのビルドと dry-run デプロイで検出する。Cloudflare 固有のコードは `apps/web/src/server` と設定ファイルに閉じ込める。
- `PageDO` と `ProjectDO` の間は結果整合になる。索引の更新が遅れても編集は成功させ、索引は再構築できるようにする(P3で設計)。
