# ADR-0005: エディタは自前の行指向モデルで作る

- 状態: 採用(P1の最初に、日本語入力の検証で再確認する)
- 日付: 2026-11-11

## 状況

再現したい操作感の中心は次の3点である。

- すべてが「行」で、行頭の空白の数だけで構造が決まる。
- カーソルのある行だけ記法がそのまま見え、他の行は装飾された表示になる。
- インデントされたかたまり(ブロック)を、まとめて字下げ・移動できる。

加えて、同期([ADR-0006](0006-sync-model.md))は行にIDを振って行う。

## 決定

- エディタの状態(行の配列とカーソル)と操作(コマンド)を、`packages/editor-core` に純粋関数として実装する。コマンドは状態を受け取り、新しい状態を返す。
- 画面は、この状態を描画する薄い層にする。文字入力は非表示の textarea で受け取り、カーソルと選択範囲は自前で描画する。
- 行の表示は `packages/parser` の解析結果から作る。

## 理由(ユーザーストーリーから)

- **US-01 / US-03**: 行とブロックの操作が仕様の大半を占める。モデルが行の配列であれば、仕様をそのままテストに書ける(例: 「インデントされた行で改行すると、新しい行が同じインデントを引き継ぐ」)。
- **US-04**: 行IDと編集操作の対応を自分で管理できる。汎用エディタでは、内部の文書モデルと行IDの対応を別に維持する必要がある。
- TDDとの相性が良い。操作のほぼすべてをブラウザなしで検証できる。

## 検討した他の案

| 案                         | 採用しなかった理由                                                                                                                                 |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| CodeMirror 6               | 日本語入力とモバイル対応は堅牢。ただし、行IDの追跡と「カーソル行だけ生の記法」の表示を拡張機能として実装することになり、操作感の細部を合わせにくい |
| ProseMirror / Tiptap       | 文書を木構造で持つ前提で、「すべてがただの行」というモデルと合わない                                                                               |
| contenteditable を直接使う | ブラウザごとの挙動の差が大きく、テストで仕様を固定しにくい                                                                                         |

## リスクと対策

- **日本語入力(IME)**: 変換中の文字列の表示位置と確定の扱いを自前で実装する必要がある。P1の最初に検証用の実装を作り、E2Eテストで変換操作を確認する。
- 解決できない問題が出た場合は、描画と入力の層だけを CodeMirror 6 に置き換える。モデルとコマンドは `editor-core` に分離してあるので、置き換えの範囲は描画層に限られる。この場合は新しいADRを書く。
