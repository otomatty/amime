# ADR-0013: 複数行にまたがる記法(コードブロックとテーブル)の扱い

- 状態: 採用
- 日付: 2026-11-12
- 関連: [ADR-0012](0012-inline-notation.md) の「まだ扱っていないもの」のうち、コードブロックとテーブルへの回答

## 状況

コードブロックとテーブルは、始まりの行(`code:名前`、`table:名前`)と、それに続くインデントされた行からなる。ある行がブロックの中身かどうかは、その行だけを見ても決まらない。一方、ADR-0012 の解析は行ごとに独立している。

## 決定

### 行の役割を、ページ全体から先に決める

- `classifyLines` が、ページのすべての行に役割を付ける: タイトル、本文、コードブロックの始まり・中身、テーブルの始まり・行。
- ブロックの中身は、始まりの行より深くインデントされた行が続くあいだ。同じか浅いインデントの行(空行を含む)でブロックは終わる。
- 1行目はタイトルなので、`code:` で始まっていてもブロックを始めない。
- `parseLine` は、行と役割を受け取って解析する。行ごとに独立という性質は保つ。
- 役割の判定は行数に比例する軽い処理なので、編集のたびにページ全体について行う。行の描画には役割を文字列と数値で渡すので、役割が変わらない行は描画し直さない。

### コードブロック

- 始まりの行は、`code:` を隠して名前を見出しとして表示する。編集中は `code:` も見せる。
- 中身の行は、始まりの行より1つ深いところまでをインデントとし、それより後ろは空白も含めてそのままコードとして表示する。記法は解釈しない。

### テーブル

- 行は、インデントのあとをタブでセルに分ける。セルの中では行内の記法を解釈する。括弧やバッククォートは、セルをまたいで対にならない。
- 連続するテーブルの行を1つの枠で囲み、CSSの表(`display: table`)として配置する。行は別々の要素のままで、列の幅だけをブラウザにそろえさせる。
- セルの区切りのタブは描画しない。セルの中の余白を押したら、そのセルの中で位置を決める(左の余白ならセルの先頭、それ以外ならセルの末尾)。
- テーブルの行では、Tab キーはインデントではなくタブ文字の入力(新しいセル)になる。Shift+Tab は、ほかの行と同じくインデントを浅くする。

### 行頭で決まる1行の記法

- `$ ` または `% ` で始まる行はコマンド行、`? ` で始まる行はヘルプ行として、行全体を等幅の文字で表示する。中の記法は解釈しない。

## 根拠

- コードブロックとテーブルの書き方は、利用者が公開している記法の説明(「記法」「記法サンプル」などのページ)で確認した。`code:言語名`、`code:ファイル名`、`code:ファイル名(言語名)` の形があり、テーブルは「インデントしてタブ区切り」で書く。
- 「コードブロックの宣言はインデントを除く行頭に必要」「始まりの行より深い行が中身」という規則は、利用者が公開している解析の説明と一致する。

## こちらで決めた挙動

| 項目                               | 決めた挙動                                           |
| ---------------------------------- | ---------------------------------------------------- |
| 名前のない `code:` や `table:`     | ブロックの始まりにしない                             |
| テーブルのセルの中の記法           | 解釈する(リンクやインラインコードを書ける)           |
| セルの中での引用・コマンド行       | 解釈しない(行頭で決まる記法は、セルには当てはめない) |
| テーブルの行の Shift+Tab           | インデントを浅くする                                 |
| コードやテーブルの行の箇条書きの印 | 付けない                                             |

## 理由

- 行をまたぐ判断を1か所(`classifyLines`)に集めると、行ごとの解析と描画は単純なままでよい。P2で同期を入れても、行が単位であることは変わらない。
- テーブルの列の幅は、中身の文字の幅で決まる。自前で測って計算するより、ブラウザの表の配置に任せるほうが確実で、折り返しや文字の大きさの違いにも追従する。
- セルごとに記法の対応(括弧、バッククォート)を求め直すので、あるセルに書いた `[` が別のセルの表示を壊さない。

## まだ扱っていないもの

- コードの色分け(シンタックスハイライト)と、`code:ファイル名(言語名)` の言語名の解釈。
- 同じ名前のコードブロックをつなげて取り出す機能、コードのコピー、テーブルのCSVでの取り出し。
- ヘルプ行の、検索の入口としての働き(いまは見た目だけ)。
- テーブルの読み上げ(スクリーンリーダーに表として伝えること)。[#3](https://github.com/otomatty/amime/issues/3) とあわせて扱う。
