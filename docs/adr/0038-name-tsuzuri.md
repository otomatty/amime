# ADR-0038: 名前を Tsuzuri(綴)にする

- 状態: 採用
- 日付: 2026-11-15
- 関連: [ADR-0002](0002-scope-and-non-goals.md)(仮称 Amime)、[ADR-0032](0032-login-and-sessions.md)(Cookie の名前)、[ADR-0037](0037-ci-and-deploy-workflows.md)(デプロイ)

## 状況

ADR-0002 では、名前を仮称 **Amime(網目)** としていた。依頼者から名前を変えたいという相談があり、候補の中から **Tsuzuri(綴)** に決まった。

「綴る」には、文章を書くことと、紙を綴じ合わせることの、両方の意味がある。書いたページをリンクで綴じていくこのアプリの性質と、見た目の方針「静かな紙」(ADR-0036)に合う。

本番へは、まだ一度もデプロイしていない。Worker やデータベースの名前を変えても、移すデータや、ログインし直す利用者はいない。

## 決定

- 画面に出す名前は **Tsuzuri**。見出し、ページのタイトル(`<title>`)、ログインしていないときの案内に使う。文書の題名では「Tsuzuri(綴)」と書く。
- 名前を含む識別子も、すべて変える。
  - パッケージ: `@amime/*` → `@tsuzuri/*`。ルートは `tsuzuri`
  - Worker: `amime` → `tsuzuri`(本番のURLは `https://tsuzuri.(サブドメイン).workers.dev`)
  - D1 のデータベース: `amime` → `tsuzuri`
  - Cookie: `amime_session` → `tsuzuri_session`、`amime_login` → `tsuzuri_login`(ADR-0032 の名前を置き換える)
  - 端末に残す未送信の変更のキー: `amime:pending:` → `tsuzuri:pending:`
  - テストで使うホスト名: `amime.test`、`amime.example` → `tsuzuri.test`、`tsuzuri.example`
- 採用済みの ADR の本文に出てくる「Amime」は、そのときの記録として残す(ADR-0011)。
- GitHub のリポジトリ名(`otomatty/amime`)は、この変更では変えない。リポジトリの設定は依頼者のアカウントの操作なので、変えるかどうかは依頼者が決める。

## 理由

- 最初のデプロイの前に変えれば、Worker の名前もURLもデータベースも、作り直しや移行をせずに済む。デプロイの後だと、URLが変わり、データベースを移し、利用者は全員ログインし直すことになる。
- 識別子に旧名を残すと、画面の名前とコードの名前がずれて、読むときに迷う。

## 他の案

- **画面の名前だけを変え、識別子は残す**: 差分は小さい。ただ、Worker の名前は本番のURLに出るので、デプロイの後に変えるのが難しい。旧名がコードに残り続ける。
- **「綴」を画面に出す**: 漢字一字は、英字のURLやパッケージ名と見た目が揃わない。文書の題名で添えるだけにした。

## 結果

- 手元の開発環境では、Cookie と端末のキーが変わる。前の名前でのログインと、まだ送っていない変更は、引き継がれない(手元で試していたものだけ)。
- 同じ「Tsuzuri」という名前の、日本語の執筆ソフトがある。一般に公開するときは、紛らわしさや商標を、依頼者が確かめる必要がある。
- Cloudflare の手順([#33](https://github.com/otomatty/amime/issues/33))に出てくる Worker とデータベースの名前は、`tsuzuri` になる。
