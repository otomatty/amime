# ADR-0004: モノレポの構成と依存の境界

- 状態: 採用
- 日付: 2026-11-11

## 状況

記法の解析、エディタの操作、同期の規則は、クライアントとサーバーの両方で同じ結果にならなければならない。また、これらは仕様の中心であり、最も厚くテストしたい。

最初の提案では `apps/web`(SPA)と `apps/worker`(API)を別パッケージにしていた。しかし `cf` では、Worker が配信する静的アセットは同じ Vite プロジェクトのクライアントビルドから取られる。別パッケージにすると、設定の二重管理かビルドの迂回が必要になる。

## 決定

- pnpm workspace のモノレポにする。
- デプロイ単位は `apps/web` の1つにまとめ、その中を `src/client` と `src/server` に分ける。
- 仕様にあたるロジックは `packages/` に純粋関数として置く(`shared`、`parser`、`editor-core`、`sync`)。
- パッケージはビルドせず、TypeScript のソースを直接読み込む(`exports` が `src/index.ts` を指す)。
- 境界は次の手段で機械的に守る。

| 境界                                                | 手段                                                                 |
| --------------------------------------------------- | -------------------------------------------------------------------- |
| `packages/*` はフレームワークと実行環境に依存しない | Biome `noRestrictedImports`、tsconfig から DOM と Workers の型を外す |
| `client` と `server` は互いを読み込まない           | Biome `noRestrictedImports`、tsconfig を分ける                       |
| 宣言していないパッケージを読み込まない              | pnpm の厳格な node_modules、knip                                     |

## 理由

- 純粋関数にしておくと、Node 上で高速にテストでき、TDDの1サイクルが数秒で回る。
- 同じ `sync` パッケージをクライアントとサーバーが使うので、「クライアントでは適用できたがサーバーで拒否された」という食い違いが原理的に起きない。
- 提案との食い違いは、[ADR-0001](0001-record-decisions.md) の手順どおり「上位(基盤の制約)に合わせて下位(提案の構成)を直し、守りたかった性質(クライアントとサーバーの分離)は Lint で保つ」形で解消した。

## 影響

- `apps/web` には tsconfig が3つある(client / server / node)。実行環境ごとに使える型が違うためである。
- パッケージをビルドしないので、外部に公開する場合はビルド手順を追加する必要がある。
