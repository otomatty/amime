# ADR-0031: 本文からページを探す

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した)
- 日付: 2026-11-13
- 関連: [ADR-0029](0029-search-pages-by-title.md)(名前で探す。探す欄に、本文から探す項目を足す)、[ADR-0025](0025-page-index-and-list.md)(台帳への反映)、[ADR-0003](0003-platform-cloudflare.md)

## 状況

名前で探す(ADR-0029)だけでは、どのページに書いたか覚えていない言葉から、ページにたどり着けない(US-10)。
ページの本文は、ページごとの `PageDO` に分かれている。プロジェクトの全体を探すには、本文を1か所に集めておく必要がある。

## 決定

### 本文を、台帳に写す

- `PageDO` は、書き換えが落ち着いてから台帳に知らせるとき(ADR-0024)、ページの**本文**(すべての行を改行でつないだもの)も渡す。
- 台帳(`ProjectDO`)は、ページごとに、本文と、**照らし合わせるための形**にした本文を持つ。
  - 照らし合わせるための形は、Unicode の互換の正規化(NFKC)をして、小文字にそろえたもの。大文字と小文字、全角と半角の違いを区別しない。
- 持つのは、20万文字(UTF-16 の符号単位)まで。それより後ろは、探す対象にならない。`PageDO` も、そこまでしか渡さない。
- ページを削除したら、写した本文も消す。

### 探し方

- 入力を、空白で語に分ける。**すべての語を本文に含む**ページを返す(1行目の名前も、本文に含める)。語は、そのままの並びで含まれていれば合う(名前で探すときのような、飛び飛びの一致はしない)。
- 探すのは、SQL の `instr`(部分文字列の検索)で行う。索引は使わず、写した本文をすべて調べる。
- 語の数や長さで、入力を切り捨てない。同じ語は、1つにまとめる。SQL の条件にするのは40語まで(1つの問い合わせに書ける条件の数に、限りがある)。それを超える語があるときは、40語ずつに分けて探し、そのすべてで見つかったページを残す。返す件数、「ほかにも合うページがあるか」、名前にすべての語があるかは、すべての語で決める。
- 名前(1行目)にすべての語があるページを先に、あとは更新が新しい順に並べる。
- `GET /api/pages/search?q=…&limit=…` が、既定で20件、最大50件を返す。ほかにも合うページがあるかどうかも返す。
- 見つかったページには、**語を含む行**を3行まで添える。行は、記法の記号を除いた、読める文字列にする。長い行は、語のまわりの120文字だけにする。

### 画面

- 探す欄(ADR-0029)に入力があるあいだ、名前の候補のあとに「本文から探す」の項目を出す。合う名前がなければ、この項目が選ばれている(Enter で、本文から探す)。
- 本文を探した結果は、トップに `?q=語` を付けたURLで表示する。再読み込みしても、共有しても、同じ結果になる。
- ページのAPIが無効な環境(公開環境。ADR-0009)では、探す欄を出さない。`?q=語` の付いたURLを開いたときは、トップと同じに、試し書きのページを表示する。
- 結果には、ページの名前、語を含む行、更新した時刻を並べる。語に合うところに、印を付ける。

## 理由(ユーザーストーリーから)

- **US-10**「本文の全文検索ができる。日本語でも検索できる」に対応する。
- 日本語は、単語の区切りがない。単語に分けて索引を作る方式では、分け方と合わない言葉(複合語の一部、送り仮名のゆれ)が見つからない。部分文字列で探せば、書いたとおりの言葉が、2文字でも見つかる(「牛乳」「会議」)。

## 検討した他の案

| 案                                                        | 採用しなかった理由                                                                                                                                                                          |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SQLite の全文検索(FTS5)を、3文字ごとの索引(trigram)で使う | 3文字より短い語は索引を使えず、すべて調べることになる。日本語では2文字の語が多いので、すべて調べる道は、どちらにしても要る。まず、その道だけで作る。遅くなったら、3文字以上の語のために足す |
| FTS5 を、標準の単語分割(unicode61)で使う                  | 日本語を、空白のないひと続きの単語として扱う。文の途中の言葉が見つからない                                                                                                                  |
| 探すたびに、すべての `PageDO` に問い合わせる              | ページの数だけ呼び出しが要る                                                                                                                                                                |
| D1 に、本文を集める                                       | 台帳(`ProjectDO`)と別に、もう1つ保存先を持つことになる。プロジェクトごとの分離と、反映の一貫性を、作り直すことになる                                                                        |
| 外部の検索サービス、または Vectorize(意味で探す)          | 費用と外部アカウントが増える。言葉そのもので探すことが、先に要る                                                                                                                            |
| 記法の記号を除いた文字列だけを、台帳に写す                | リンク先のURLや、コードの中の記号で探せなくなる。添える行だけ、読める文字列にすれば足りる                                                                                                   |
| 名前で探すのと同じ、飛び飛びの一致を、本文にも使う        | 本文は長いので、ほとんどのページが合ってしまう                                                                                                                                              |

## わかっている制約

- 探すたびに、プロジェクトのすべてのページの本文を調べる。ページが非常に多い(数万を超える)プロジェクトでは、遅くなる。そのときは、FTS5 の trigram を足すことを、あらためて決める。
- この変更より前に保存したページは、次に変更されるまで、本文から探せない(本文が、まだ台帳に写されていない)。
- 探せるのは、台帳に反映された本文である(書き換えが落ち着いてから約2秒後)。書いた直後の言葉は、すぐには見つからない。
- ひらがなとカタカナの違い、漢字の読み、活用のゆれ(「買う」と「買った」)は、区別する。前の文字と合わさって1つの形になる文字(濁点が別の文字になっている半角カナなど)は、合わさった形で照らし合わせる(「ｶﾞ」は「ガ」に合い、「カ」には合わない)。
- 合わさる文字が64文字を超えて続くところ(ふつうの文章にはない)では、印が付かないことがある。
- 語が行をまたいで書かれているときは、合わない(語は、改行を含まない)。別々の語が別々の行にあるのは、合う。
- 本文は、ページごとの `PageDO` と、台帳の両方に持つ。台帳には、元の本文と、照らし合わせるための形の、2つを持つ。保存する量は、本文のおよそ3倍になる。
- 20万文字を超える本文の、超えた部分は探せない。
- 語が40を超えるときは、40語ごとに、すべてのページの本文を調べる(語が多いほど、遅くなる)。合ったページの名前と更新の時刻を、すべて取り出してから並べる。
- 結果は50件まで。それより多いときは、語を足して絞り込む(続きを取り出す方法は、まだない)。
- 添える行は、記法の記号を除いた文字列で探す。URLやコードの記号にだけ合ったページは、行が添えられない。
