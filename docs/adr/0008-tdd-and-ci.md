# ADR-0008: テスト先行の運用と、CIでの強制

- 状態: 採用
- 日付: 2026-11-11

## 状況

再現の対象である本家の仕様は、すべてが文書化されているわけではない。仕様を確定させる場所が必要である。また、開発の大半をAIが行うため、「動いているように見えるが検証されていないコード」が入り込むのを機械的に防ぎたい。

## 決定

### テストを仕様の置き場所にする

- 公開ヘルプと、利用者として観察した挙動を、入力と期待結果の例としてテストに書く。
- テスト名は、利用者から見た振る舞いを日本語の文で書く。テスト名の一覧が、そのまま仕様の一覧になる。
- 本家と意図的に変える挙動は、テストと feature-matrix.md の両方に書く。

### Red → Green → Refactor で進める

失敗するテストを先に書き、通す最小限の実装を書き、通したまま整理する。

### CIで検査すること

「テストを先に書いたか」という順序は、機械では検査できない。代わりに、テストのない実装が入らないことを3つの検査で保証する。

| 検査                           | 内容                                                        | 実装                            |
| ------------------------------ | ----------------------------------------------------------- | ------------------------------- |
| テストの存在                   | 変更した実装ファイルの隣にテストファイルがある              | `scripts/check-test-first.ts`   |
| 振る舞いの変更にはテストの変更 | `feat` / `fix` のPRがテストファイルの変更を含む             | 同上(PRタイトルの種別で判定)    |
| カバレッジ                     | `packages/*` と `scripts/lib` は 100%、`client` は 80% 以上 | Vitest の `coverage.thresholds` |

`refactor` などの種別では、テストの変更を要求しない。振る舞いを変えない整理は、既存のテストが通り続けることが検証になるためである。

### CIの構成

`.github/workflows/ci.yml` の5つのジョブを、PRと `main` へのプッシュで並列に実行する。

| ジョブ | 内容                                                           |
| ------ | -------------------------------------------------------------- |
| static | Lint、型検査、未使用コード、PRタイトルの規約、テスト先行の規約 |
| unit   | 単体テストとカバレッジ                                         |
| server | Workers ランタイム上のテスト                                   |
| build  | ビルドと、アップロードしないデプロイ検証                       |
| e2e    | 実ブラウザでのテスト                                           |

5つすべてが通ったあと、リポジトリ変数 `DEPLOY_ENABLED` が `true` の場合だけ、PRではプレビュー環境へ、`main` では本番へデプロイする([deploy.md](../deploy.md))。

## 理由

- カバレッジ 100% は、純粋関数のパッケージに限れば現実的に維持できる。ここは仕様そのものであり、検証されていない分岐を許す理由がない。
- UIは表示の細部まで網羅すると変更に弱くなるため、閾値を 80% にして、操作と表示の結び付きを中心に検証する。
- サーバーのテストは別のランタイムで動くため、カバレッジの計測対象には含めていない。振る舞いは Durable Object のRPCとHTTPのテストで検証する。

## 限界

- カバレッジは「実行された」ことを示すだけで、「検証された」ことは保証しない。レビューでテストの検証内容を確認し、P2でミューテーションテストの導入を検討する([ADR-0007](0007-tooling.md))。
- テスト先行の検査は、テストファイルが存在することだけを見る。空のテストはカバレッジの閾値で検出する。
