# ADR-0025: 台帳に索引を持たせ、トップをページの一覧にする

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した)
- 日付: 2026-11-13
- 関連: [ADR-0024](0024-page-identity-and-project-index.md)(台帳に、索引の内容を足す)、[ADR-0003](0003-platform-cloudflare.md)、[ADR-0017](0017-page-storage-and-api.md)(トップの試し書きを、一覧に置き換える)

## 状況

プロジェクトにどんなページがあるかを、見渡す方法がなかった(US-09)。ページは、URLを知っていれば開けるだけだった。

ページの本文は、ページごとの `PageDO` に分かれている。一覧のたびにすべての `PageDO` を読むことはできない。台帳(`ProjectDO`。ADR-0024)に、一覧に必要な情報を写しておく。

## 決定

### 台帳に、ページの要約を写す

- `PageDO` は、書き換えが落ち着いてから台帳に知らせるとき(ADR-0024)、1行目に加えて、ページの**要約**を渡す。
  - **冒頭の本文**: タイトルの次の行から、空でない行を5行まで。記法の記号を除いた、読める文字列にする。1行は200文字まで。
  - **画像**: ページの中の最初の画像のURL。
  - **リンク先**: ページの中の `[ページ名]` と `#タグ` の名前。同じ名前は1つにまとめる。1ページ1,000件まで。
- 要約は、記法の解析(`@amime/parser`)と同じ規則で、`summarizePage` が作る。コードブロックの中や1行目は、リンクとして読まない。
- 台帳は、要約をページの行に持ち、リンク先を別の表(どのページから、どの名前へ)に持つ。リンク先は、変わった分だけを書き込む。
- リンク先は、**名前**(正規化したもの)で持つ。まだないページへのリンクも持てる。名前を変えたページは、新しい名前へのリンクから数え直される。

### ページの一覧

- `GET /api/pages?sort=…&limit=…&offset=…` が、保存されたページの一覧を返す。開いただけのページ(ADR-0024)は含めない。
- 並び順は4つ。更新が新しい順(既定)、作成が新しい順、名前の順、リンクされている数が多い順。同じ値のページは、名前の順にする。
- 「リンクされている数」は、そのページの名前へリンクしている、他のページの数。自分へのリンクは数えない。
- 1度に取り出すのは100件まで。続きは、何件目からかを指定して取り出す。

### トップ

- トップ(`/`)は、ページの一覧にする。ページをカードとして並べ、名前・冒頭の本文・画像・更新した時刻を見せる。
- 並び順を選べる。選んだ並び順はURL(`?sort=`)に残す。
- 名前を入れて、新しいページを書き始められる(その名前のURLへ移る)。
- 見出し「Amime」から、どのページからでもトップへ戻れる。
- 試し書きのページ(保存されない)は、ページのAPIが無効な環境(公開環境。ADR-0009)ではこれまでどおりトップに表示する。有効な環境では `/?playground` で開く。

### 台帳の保存の形

- 台帳の表の形を変えるときは、移行を末尾に足す。適用した数を台帳に覚えておき、開いたときに足りない分だけを適用する。

## 理由(ユーザーストーリーから)

- **US-09**「ページがカードとして並び、タイトル・冒頭・画像が見える」「更新日時・作成日時・リンクされている数などで並べ替えられる」: 一覧に必要な情報を、台帳だけで答えられるようにする。
- **US-07**: リンク先を台帳に持つ。関連ページと、まだないページへのリンクの区別は、この表から求める(このあとの変更で入れる)。
- **US-04**: 要約は、編集の応答を待たせないアラームの中で作る(ADR-0024)。

## 検討した他の案

| 案                                             | 採用しなかった理由                                                                                          |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 一覧のたびに、ページごとの `PageDO` を読む     | ページの数だけ呼び出しが要る。並べ替えもできない                                                            |
| 要約を、画面の側で作って送る                   | 画面を通らない変更(名前を変えたときのリンクの書き換えなど)で、要約が古くなる。信頼できない入力にもなる      |
| 冒頭の本文を、記法のまま台帳に持ち、画面で描く | カードには、読める文字列があれば足りる。記法の解析を一覧のたびに行うことになる                              |
| リンク先を、ページIDで持つ                     | まだないページへのリンクを表せない。名前を変えたときに、リンクの書き換え(US-08)とは別に、表の付け替えも要る |
| 件数を制限せず、すべてのページを1度に返す      | ページが増えると、応答が大きくなる                                                                          |

## わかっている制約

- 一覧に反映されるのは、書き換えが落ち着いてから(2秒後。ADR-0024)である。
- この変更より前に保存したページは、次に変更されるまで、冒頭の本文と画像が空のまま一覧に出る。リンクされている数にも数えられない。
- 「リンクされている数が多い順」は、取り出すたびに数える。ページとリンクが非常に多いプロジェクトでは、遅くなる。
- 続きを取り出しているあいだにページが増えたり並びが変わったりすると、続きが前の分と重なったり、1件抜けたりする。画面は、同じページを2度並べない。
- ページを一覧の先頭に固定すること(US-09)と、ページの削除は、まだない。
- カードの画像は、ページに書かれたURLをそのまま読み込む。読み込み先には、見ているページのURLを伝えない。
