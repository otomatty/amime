# ADR-0043: プロジェクトを、1つのファイルに書き出し、読み込めるようにする

- 状態: 採用
- 日付: 2026-11-17
- 関連: [US-14](../user-stories/README.md)(データを持ち出せる)、[ADR-0002](0002-scope-and-non-goals.md)(本家との互換は不要)、[ADR-0024](0024-page-identity-and-project-index.md)(ページのIDと台帳)、[ADR-0032](0032-login-and-sessions.md)〜[ADR-0034](0034-invites-and-members.md)(権限)

## 状況

Tsuzuri は本番で使われ始めた。プロジェクトの全ページを、手元に持っておく手段がない。誤って消したときに戻せず、別のプロジェクトへ移すこともできない(US-14)。

ページの本文は、ページごとの Durable Object(PageDO)にある。台帳(ProjectDO)も本文を写しているが、本文を探すための写しで、長いページは途中までしかない(ADR-0031)。バックアップには使えない。

## 決定

### ファイルの形式

独自の形式の JSON にする(本家との互換は不要。ADR-0002)。

```json
{
	"format": "tsuzuri-project",
	"version": 1,
	"project": "notes",
	"exportedAt": "2026-11-17T01:02:03.000Z",
	"pages": [
		{
			"title": "買い物",
			"lines": ["買い物", "牛乳"],
			"pinned": false,
			"created": 1794878254583,
			"updated": 1794878254608
		}
	]
}
```

- ページは、名前と、すべての行の本文、一覧の先頭に固定していたか、作った時刻と最後に変えた時刻を持つ。作った順に並べる。
- 名前は、台帳の名前にする。ふつうは1行目と同じだが、1行目が空、長すぎる、ほかのページと同じ名前のときは、名前は元のまま残り、1行目と違う(ADR-0024)。1行目を名前にすると、そのページを読み込めなくなる。
- 行IDは入れない。読み込むときに付ける(下)。
- `format` で、このアプリのファイルかを見分ける。形を変えるときは `version` を上げ、古い版も読めるようにする。読めない版(新しい版)は、そう知らせる。
- 1ページでも形が違えば(行がない、行の中に改行がある、行が長すぎる、名前が空、など)、ファイルごと読み込まない。どこまで復元したかが分かりにくくなるため。
- 作った時刻と変えた時刻は、記録のために入れる。読み込んだページは、読み込んだ時刻に作ったものになる。

判定は `packages/sync` の純粋関数(`buildProjectFile`、`parseProjectFile`、`firstLineHolder`、`importLineIds`、`planPageImport`)にする。

### 書き出しと読み込みは、画面から、いつものAPIで行う

新しいAPIは作らない(既存のAPIの応答に、1つ項目を足す。下)。

- **書き出し**: 一覧(作った順)を最後までたどり、それぞれのページの本文を読み、ファイルにしてブラウザに保存させる。4ページずつ並べて読む。1ページでも読めなければ、途中までのファイルにせず、失敗を知らせる(足りないバックアップを作らない)。
- **読み込み**: ページごとに、名前で開き(台帳がIDを決める)、本文が空なら、すべての行を送る。行は、1回のコミットに収まる大きさ(変更の数と本文の長さ。画面からの保存と同じ `splitChanges`)ごとに分ける。固定していたページは、固定する。1ページずつ行う。
- **名前と1行目が違うページは、2回に分けて作る**: まず、1行目を名前にして、すべてのページを作る。すべてのページを作ったあとで、1行目を元の本文に戻す。台帳は、行を足したページの名前を1行目に合わせ、そのとき、まだ行のないページの名前は空いているものとして扱う。1行目から作ると、1行目がほかのページの名前のページが、その名前を取ってしまう(どちらを先に作っても、取られる組み合わせがある)。先に、すべてのページが自分の名前を持てば、1行目を戻したとき、台帳は名前を変えない(元のプロジェクトと同じ)。ページが台帳に載る(保存されたページになる)のは、保存の数秒後なので、1行目を戻す前に、1行目の名前を持つページ(ファイルの中にあれば)が、保存されたページとして台帳に載るまで待つ(最大20秒)。確かめるために、IDからページを引くAPI(`GET /pages/:id/info`、ADR-0042)の応答に、保存されているか(`saved`)を足す。名前で探すAPIは、名前の似たページが多いと、候補に入らないことがあるので使わない。そのページを作れなかったか、載らなければ、1行目を戻さず、送れなかったページとして知らせる(やり直すと仕上げる)。
- **一覧は、新しいページが見つからなくなるまで、たどり直す**(3回まで)。一覧は何件目からを指して取り出すので、取り出しているあいだに、取り出し終えた範囲のページが消されると、後ろのページが前にずれて、取りこぼす。
- **行IDは、ファイルとページから決める**(プロジェクトの名前、書き出した時刻、ページの名前のハッシュと、行の番号)。同じファイルの同じページなら、いつも同じ ID になる。
- **同じ名前のページがあれば、書き換えずに飛ばす。** 読み込みで、いまのページを失わない。結果に、作ったページ、飛ばしたページ、送れなかったページの名前を出す。
- **途中で止まったページは、やり直すと続きから作る。** 1ページが複数のコミットになり、途中で失敗すると、先に送った行だけが残る。やり直したとき、いまのページの行が、行IDも本文も、読み込む行の先頭と同じで(1行目は、名前か元の本文)、行の数がコミットの区切りにあたり、ページの版が、送ったコミットの数と合うなら、続きだけを行う(固定だけ、1行目を戻すだけ、のこともある)。版は、変更の効いたコミットごとに1つ進むので、読み込んだあとで編集されたページ(末尾の行を消した、など)は、版が合わず、書き換えない。それ以外のページは、同じ名前の、ほかのページとして扱い、書き換えない。

### だれが使えるか

- 書き出しは、プロジェクトのメンバー(管理者とメンバー)。設定の画面に出す。
- 読み込みは、管理者だけ(画面に出すのを、管理者だけにする)。

## 理由

- 書き出しをサーバーの中で行うと、1回の要求の中で、ページの数だけ Durable Object を呼ぶ。Workers には、1回の要求の中で出せる要求の数に上限がある。画面から1ページずつ読めば、この上限にかからず、ページが多くても進み具合を出せる。
- いつものAPIを使うので、ログインの状態とプロジェクトの権限は、それぞれのAPIが、これまでどおり確かめる(ADR-0032〜0034)。新しい穴を作らない。
- 同じ名前を飛ばすのは、読み込みを、いつでも安全にやり直せるようにするため。上書きは、元に戻せない。
- 読み込みを1つずつにするのは、行を足したときに台帳が決める名前が、ほかのページの名前に影響するため。
- 行IDをファイルから決めると、やり直しのために、読み込みの状態をどこにも残さなくてよい。ほかの人が作ったページの行IDと重なることは、まず起きない(行IDは、ふつうは、ランダムな値から作る)。また、同じ ID の行を足す変更は何もしないので、2人が同じファイルを同時に読み込んでも、行は重ならない。

## 他の案

- **サーバーに、書き出しと読み込みのAPIを作る**: 1回の要求で済むが、上の上限にかかる。ページの多いプロジェクトでは、途中で失敗する。
- **台帳の本文の写しから書き出す**: 1回の呼び出しで済むが、長いページは途中までしかない。
- **同じ名前のページを、上書きする(または「名前 (2)」として作る)**: 上書きは、いまの本文を失う。別の名前で作ると、読み込むたびにページが増える。必要になったら、選べるようにする。
- **本家の形式**: 互換は不要との回答(ADR-0002)。

## 結果

- 読み込みの権限は、画面で分けているだけで、サーバーは分けていない。読み込みは「ページを作る」ことの繰り返しなので、メンバーなら、もともとできる操作である。
- 保存した直後のページは、一覧(台帳)に載るまでの数秒のあいだ、書き出しに入らない。
- 書き出しのあいだに、何度もページが消されると、たどり直しても取りこぼすことがある。取りこぼさないためには、一覧を、何件目かではなく、作った時刻とIDで区切って取り出すAPIが要る。必要になったら、作る。
- 名前と1行目が違うページは、読み込んだあとで、1行目を戻すまでのあいだ、1行目が名前になっている。
- 2人が、違うファイル(違う時刻に書き出したもの)を、同時に同じプロジェクトへ読み込むと、まだないページに、両方の行が入ることがある。どちらも消えないので、手で直せる。
- 元のプロジェクトで、1行目が、ほかのページに取られていたために名前と違っていたページは、その名前のページがファイルにないと、読み込んだときに1行目の名前になる(元のプロジェクトでも、次に保存したときに、そうなる)。
- ページの多いプロジェクトでは、書き出しと読み込みに時間がかかる(ページごとに1〜3回の要求)。進み具合を出す。
- 履歴(ページの変更の記録)と、メンバー、招待リンクは、書き出さない。
- 画像のアップロード(US-13)を入れたら、画像をどう書き出すかを、改めて決める。
