# ADR-0024: ページを変わらないIDで識別し、プロジェクトに台帳を置く

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した)
- 日付: 2026-11-13
- 関連: [ADR-0003](0003-platform-cloudflare.md)(`ProjectDO` を、ここで実装する)、[ADR-0017](0017-page-storage-and-api.md)(ページの識別のしかたと、APIのパスを、このADRで置き換える)、[ADR-0020](0020-pending-changes-on-device.md)(端末内の記録のキーを、このADRで置き換える)

## 状況

これまで、ページは「URLの中の名前」で識別していた(ADR-0017)。名前がそのまま保存先(`PageDO`)の名前になっていた。

この方式では、ページの名前を変えられない(US-08)。名前を変えるには、保存先ごと中身を移す必要がある。ページの一覧やリンクのつながり(US-07、US-09)を作るにも、プロジェクトにどのページがあるかを知っている場所が要る。

P3 の機能(一覧、関連ページ、リンクの書き換え、検索)は、どれもこの上に載る。先に、識別のしかたを決める。

## 決定

### ページは、変わらないIDで識別する

- ページは、**ページID**(`PageId`)で識別する。保存先は `PageDO`(名前は「プロジェクト/ページID」)。
- ページの**名前**(タイトル)は、ページの1行目である。名前を変えても、IDは変わらない。
- 名前は、プロジェクトの中で重ならない。大文字小文字と、空白かアンダースコアかの違いは、同じ名前として扱う(`toTitleLc`。これまでと同じ)。

### プロジェクトごとに、台帳(`ProjectDO`)を置く

- 1プロジェクト = 1 `ProjectDO`。名前からページIDを引く台帳を持つ(SQLite)。認証とプロジェクト(P4)が入るまで、プロジェクトは `default` の1つだけ。
- 台帳は、あとで一覧・リンクのつながり・検索の索引も持つ(ADR-0003 のとおり)。このADRでは、名前とIDの対応だけを入れる。
- ページの本文は、これまでどおり `PageDO` だけが持つ。編集の経路(`PageDO`)は、台帳を通らない。

### ページを開く

1. 画面は、URLの中の名前で台帳を引く(`GET /api/pages/by-title/:title`)。台帳は、ページID・名前・名前の状態を返す。
2. まだない名前なら、台帳は**ページIDを決めて、載せる**。このページは「開いただけ」の状態で、一覧には出ない。本文は、書き込まれるまで作られない(ADR-0017 のまま)。保存されないまま1日たつと、台帳から消える。
3. 画面は、IDでページを読み込み、IDでコミットを送り、IDで WebSocket をつなぐ(`/api/pages/:id`、`/api/pages/:id/commits`、`/api/pages/:id/socket`)。

開いただけでIDを決めるのは、開いた直後から、すべてをIDで扱うためである。端末内に残す未送信の変更(ADR-0020)も、ページIDごとに残す。書いている途中で名前が変わっても、記録が迷子にならない。

まだないページのIDは、**名前から決める**(プロジェクト・名前・0から数えた番号のハッシュ)。乱数にはしない。「開いただけ」のページが台帳から消えたあとで、同じ名前をもう一度開いても、同じIDになる。通信できないまま新しいページを書いて閉じ、何日かたってから開いても、端末内に残した変更を復元できる。その名前から決まるIDを、名前を変えたあとの前のページが使っていたら、次の番号のIDにする。

### ページの名前は、1行目に合わせる

- `PageDO` は、変更が入ったあと、書き換えが落ち着いてから(最後の変更の2秒後。変更が続いていても、最初の変更から10秒後)、台帳に「1行目・バージョン・更新時刻」を知らせる。アラームで行うので、編集の応答は待たせない。失敗したら、アラームがやり直す。
- 「まだ知らせていない変更がある」ことは、コミットと同じ書き込みの中で保存する。アラームの予約に失敗しても、同じコミットの送り直し(ADR-0021)で予約し直す。
- 台帳は、ページの名前を1行目に合わせる。前の名前は空く(開くと、まだないページになる)。
- 合わせられないときは、名前を変えずに、理由を残す。

| 場面                                   | 台帳の動き                                                            | 画面                                                                                       |
| -------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 同じ名前の保存されたページがある       | 名前を変えない(`taken`)                                               | 「1行目と同じ名前のページが、すでにあります。このページの名前は「…」のままです」と案内する |
| 1行目が空                              | 名前を変えない(`empty`)                                               | 同じように案内する                                                                         |
| 1行目が200文字を超える                 | 名前を変えない(`too-long`)                                            | 同じように案内する                                                                         |
| 1行目が「.」か「..」                   | 名前を変えない(`reserved`)。URLの中で、別の場所を指す書き方になるため | 同じように案内する                                                                         |
| 同じ名前の「開いただけ」のページがある | そのページを台帳から消して、名前を変える                              | —                                                                                          |

- 名前を取られた「開いただけ」のページが、あとから保存された場合は、重ならない名前(「名前 (2)」。名前の長さの上限に収める)で台帳に載せ直す。保存されたページが、台帳から引けなくなることはない。
- `PageDO` は、台帳の答え(いまの名前と、合わせられない理由)を、接続している端末に知らせる。画面は、URLをいまの名前に合わせる(再読み込みしても、共有しても、同じページが開く)。
- `PageDO` は、台帳の答えを覚えておき、WebSocket をつないだ直後にも送る。切れているあいだに名前が変わっていても、つなぎ直したときに追いつく。
- 1行目を空白で始めても、名前には前後の空白を含めない。

## 理由(ユーザーストーリーから)

- **US-08**「ページのタイトルを後から自由に変えたい」: 名前を変える操作を別に用意せず、1行目を書き換えるだけで名前が変わる。US-01(思いついたらすぐ書ける)と同じ手触りにする。他のページにあるリンクの書き換えは、この土台の上に、別の変更で入れる。
- **US-08**「大文字小文字と、空白かアンダースコアかの違いだけなら、同じページ」: 台帳が、正規化した名前で引く。
- **US-05**(書いたものを失わない): 名前が重なっても、本文はそのまま保存される。変えられないのは名前だけで、理由を画面に出す。
- **US-04**: 編集の経路は台帳を通らない。プロジェクトの全員のキー入力が、1つの台帳に集中しない(ADR-0003)。

## 検討した他の案

| 案                                                           | 採用しなかった理由                                                                                                                               |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 名前で識別したまま、名前を変えるときに中身を別の保存先へ移す | 本文・バージョン・受け付けたコミットの記録・つないでいる WebSocket・端末内の未送信の変更を、すべて移す必要がある。途中で失敗したときの扱いも要る |
| 名前を変える操作を、1行目の編集とは別に用意する              | 1行目とページの名前が食い違う。「1行目がタイトル」という分かりやすさを失う                                                                       |
| まだないページには、最初のコミットのときにIDを決める         | 開いてから最初の保存までのあいだだけ、名前で扱う経路が要る。端末内の記録のキーも、途中で付け替えることになる                                     |
| 名前が重なったら、自動で番号を付けて変える                   | 書いた1行目と、ページの名前が黙って食い違う。書いた人に、直してもらうほうがよい                                                                  |
| 名前の変更を、コミットの中でその場で行う                     | コミットのたびに台帳を呼ぶことになり、編集の応答が台帳に左右される。書いている途中の1行目(打ちかけの名前)が、そのまま名前になる                  |

## わかっている制約

- 名前が変わるのは、書き換えが落ち着いてから(2秒後)である。そのあいだは、前の名前で開く。新しく書いたページが台帳で「保存されたページ」になるのも、同じだけ遅れる。
- 1行目を書いている途中で2秒止まると、途中の名前がいったんページの名前になる。
- 前の名前のURLを開くと、まだないページになる(前の名前から新しい名前への案内は出ない)。他のページにあるリンクの書き換えは、まだない。
- `PageDO` と台帳は、別々に保存する。台帳への知らせが失敗し続けると、台帳の名前が古いままになる。次の変更のあとで、もう一度知らせる。
- ページIDを知っていれば、台帳にないIDへ書き込める。そのページは、重ならない名前で台帳に載る。認証(P4)が入るまで、ページのAPIは公開環境では無効である(ADR-0009)。
- 開いただけのページは、1日のあいだ台帳に残る。
- 通信できないまま新しいページを書いて閉じ、そのあいだに、他のページがその名前になった場合(だれかが同じ名前のページを作った、名前を変えた)は、その名前を開いても、端末内に残した変更を復元できない(別のページが開く)。変更は、端末内に30日のあいだ残っている(Issue #18)。
- この変更より前に保存したページ(名前で識別していた)は、開けなくなる。ページのAPIを有効にした公開環境はないので、移行は行わない。端末内に残っていた未送信の変更(名前ごとに残していた)も、引き継がない。
