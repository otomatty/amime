# ADR-0015: 行とかたまりを動かす操作(アウトライン編集)

- 状態: 採用(Mac の実機でのキーの確認が残っている)
- 日付: 2026-11-12
- 関連: [ADR-0002](0002-scope-and-non-goals.md)、[ADR-0005](0005-editor-architecture.md)、[ADR-0014](0014-selection-clipboard-undo.md)

## 状況

US-03(かたまりごと動かせる)は、行を子の行ごと字下げ・字上げすること、上下に動かすこと、それをキーボードだけで行えることを求めている。選択した行のインデント(Tab / Shift+Tab)は ADR-0014 で入れた。残っているのは、行の上下移動と、子の行を含めた操作である。

根拠にしたのは、公開ヘルプの「ショートカットキー」と「アウトライン編集」のページである。そこから読み取れるのは次のことまでで、細かい挙動は書かれていない。

- Ctrl+矢印: カーソルのある行を上下左右に動かす。選択しているときは、選択した範囲を動かす。
- Alt(Mac では Option)+矢印: カーソルを起点としたブロックを上下左右に動かす。
- OS のキーの働きが優先されることがある(例: Mac の Option+左右は単語単位の移動)。

## 決定

### 対象の行と「かたまり」

- **対象の行**は、選択していなければカーソルのある行、選択していれば選択にかかるすべての行。選択が行頭で終わっているとき、その行は対象にしない(Tab でのインデントと同じ規則)。
- **かたまり**は、対象の行に、そのすぐ下に続く「より深い行」を加えたもの。深さの基準は、対象の行のうちいちばん浅い行のインデント。
- 行の種類(コードブロックやテーブル)は見ない。コードブロックやテーブルの始まりの行にカーソルがあれば、中身は「より深い行」なので一緒に動く。中身の1行だけを動かすこともできる。ブロックの範囲はインデントから毎回決まる(ADR-0013)ので、動かした結果がそのまま新しい構造になる。

### 操作

| 操作                   | 働き                                                        |
| ---------------------- | ----------------------------------------------------------- |
| 行を上下に動かす       | 対象の行を、すぐ上(下)の1行と入れ替える。子の行は動かさない |
| かたまりを上下に動かす | かたまりを、すぐ上(下)にある「相手」と入れ替える            |
| 行を左右に動かす       | 対象の行を1段浅く(深く)する。Shift+Tab / Tab と同じ         |
| かたまりを左右に動かす | かたまりのすべての行を1段浅く(深く)する                     |

ヘルプに書かれていないため、次のように決めた。

| 場面                                                     | 決めた挙動                                               | 理由                                                                         |
| -------------------------------------------------------- | -------------------------------------------------------- | ---------------------------------------------------------------------------- |
| かたまりを上下に動かすときの相手                         | 同じ深さの行と、その子の行                               | 兄弟どうしを入れ替えるのが、構造を組み替えるときに期待される動き             |
| すぐ上(下)が、かたまりより浅い行のとき                   | その1行だけを相手にする。かたまりは親の行の外へ出る      | 端で止めると、親をまたいで動かす手段がなくなる                               |
| すぐ上に、同じ深さの行を持たない深い行が並んでいるとき   | その並びを相手にする                                     | 途中に割り込むと、他の行の親子関係を変えてしまう                             |
| 文書の先頭・末尾で、動かす先がないとき                   | 何もしない                                               |                                                                              |
| かたまりを浅くするとき、いちばん浅い行にインデントがない | 何もしない                                               | 子の行だけを浅くすると、親と同じ深さになり親子の関係が崩れる                 |
| 1行目(タイトル)をまたぐ移動                              | 特別扱いしない。1行目に来た行がタイトルになる            | タイトルは「1行目であること」だけで決まる(ADR-0013)                          |
| カーソルと選択                                           | 動かした行についていく。選択は保つ                       | 続けて同じキーを押して、何段も動かせる                                       |
| 行頭で終わる選択を、文書の末尾まで動かしたとき           | 選択の終わりを文書の末尾に置く                           | 選択の終わりは対象の行の直後の行頭にあるが、末尾まで動かすとその行がなくなる |
| 取り消し                                                 | 1回の操作を1回の取り消しにする。続けて押してもまとめない | 動かしすぎたときに、1段だけ戻せる                                            |

### キー

| キー                                          | 働き                                                      |
| --------------------------------------------- | --------------------------------------------------------- |
| Ctrl+↑ / ↓                                    | 行を上下に動かす                                          |
| Ctrl+← / →                                    | 行を浅く / 深くする                                       |
| Alt+↑ / ↓(Mac では Option)                    | かたまりを上下に動かす                                    |
| Alt+← / →(Mac 以外)                           | かたまりを浅く / 深くする                                 |
| Ctrl+Home / End(Mac 以外)、Command+↑ / ↓(Mac) | 文書の先頭 / 末尾へ動く。Shift を足すと、そこまで選択する |
| Command+← / →(Mac)                            | 行頭 / 行末へ動く。Shift を足すと、そこまで選択する       |

- 行を動かすキーは、Mac でも Control キーを使う(ヘルプのとおり)。取り消しなどが Mac で Command キーになる(ADR-0014)のとは異なる。
- **Mac の Option+左右には割り当てない。** Mac では単語単位の移動に使われるキーで、ヘルプもこの衝突に触れている。単語単位の移動はまだ実装していないが、あとで入れられるように空けておく。Mac でかたまりを浅く・深くするには、行を選択して Tab / Shift+Tab を使う。
- Mac 以外では、Ctrl+左右を行のインデントに使う。そのため、Ctrl+左右での単語単位の移動はできない。
- Ctrl・Alt・Meta のうち2つ以上を同時に押す組み合わせと、行やかたまりを動かすキーに Shift を足した組み合わせには、割り当てない(AltGr での文字入力や、OS・ブラウザのショートカットを妨げないため)。
- 文書の端へ動くキーは、ヘルプにはない。それぞれの OS で一般的な割り当てに合わせた。
- 編集欄にフォーカスがあるあいだ、割り当てのあるキーはブラウザの既定の動作を止める。Alt+左右はブラウザの「戻る・進む」でもあるが、編集欄の中ではかたまりの操作を優先する。

## 理由(ユーザーストーリーから)

- **US-03**: 「行とその子孫の行を、まとめて字下げ・字上げできる」「まとめて上下に移動できる」「キーボードだけで行える」の3つを、そのまま満たす。
- 行だけを動かす操作と、かたまりを動かす操作を分けておくと、「子を残して親だけ入れ替える」「子ごと運ぶ」を使い分けられる。ヘルプの割り当てもこの2つを分けている。
- 操作はすべて `packages/editor-core` の純粋関数(`outline.ts`)で、行の配列を並べ替えるだけにした。P2で行IDを入れたとき、並べ替えは「行の移動」として表せる(ADR-0006)。

## 確認できていないこと

- Mac の実機でのキー。Control+矢印は、macOS の標準設定では Mission Control や操作スペースの切り替えに使われており、ブラウザに届かないことがある。その場合は、OS 側の設定を変えるか、Tab / Shift+Tab と Option+上下を使う。自動テストは、キーの割り当てを決める関数に対するものだけである。
- Windows の Alt+矢印を、ブラウザや IME が先に受け取る場合があるか。自動テスト(Linux 上の Chromium)では編集欄に届くことを確認した。

## わかっている制約

- 行頭で終わる選択を文書の末尾まで動かし、その最後の行が空行だったとき、空行は選択から外れる(空行では行頭と行末が同じ位置になり、いまの選択の表し方では「文書の末尾の改行まで選択している」ことを表せない)。空行1行だけを動かした場合は選択の表示が消えるが、カーソルはその行に残るので続けて動かせる。複数行の場合は、続けて動かすと最後の空行が置いていかれる。選択の表し方を見直すときに合わせて直す([#8](https://github.com/otomatty/amime/issues/8))。

## まだ扱っていないもの

- 単語単位の移動と削除(Mac の Option+左右、Mac 以外の Ctrl+左右にあたるもの)。Mac 以外では行のインデントと衝突するので、入れるときは、どちらを優先するかを利用者が選べる設定を合わせて検討する。
- 上下移動を見た目の横位置に合わせること、ダブルクリックでの単語の選択(ADR-0014 から引き続き)。
- タッチ操作でかたまりを動かすこと(P6)。
