# ADR-0029: 名前でページを探す

- 状態: 採用(Cloudflare 上での動作は未確認。手元の Workers ランタイムで確認した)
- 日付: 2026-11-13
- 関連: [ADR-0024](0024-page-identity-and-project-index.md)(台帳)、[ADR-0025](0025-page-index-and-list.md)(一覧)

## 状況

ページを見つける方法は、一覧を見ることと、リンクをたどることだけだった。名前の一部しか覚えていないページに、すぐたどり着けなかった(US-10)。

## 決定

### 合わせ方

- 入力を、空白(とアンダースコア)で語に分ける。**すべての語が合う**名前を、候補にする。語の順は問わない。
- 大文字小文字と、空白かアンダースコアかの違いは、区別しない(ページの名前の扱いと同じ。ADR-0024)。
- 1つの語は、名前の中に**文字が順に出てくれば**合う(あいだに他の文字が挟まってもよい)。「買物」で「買い物」が見つかる。
- 合う順は、語ごとに次の順で決め、足し合わせる。同じなら、短い名前を先にする。それも同じなら、更新が新しいものを先にする。
  1. 名前の全体に一致する
  2. 名前の先頭に合う
  3. 名前の中の語(空白のあと)の先頭に合う
  4. 名前の途中に合う
  5. 文字が飛び飛びに合う(あいだに挟まる文字が少ないほど先)
- 入力が空なら、更新が新しい順に返す。
- 合わせ方は、`@amime/shared` の純粋な関数(`searchTerms`、`rankTitles`)にする。

### 探す場所

- `GET /api/pages/titles?q=…&limit=…` が、台帳(`ProjectDO`)から、保存されたページの名前を合う順に返す。既定で20件、最大50件。
- 台帳は、SQL で候補を絞る(語の文字が順に出てくる名前。`LIKE '%買%物%'`)。更新が新しいものから1,000件までを読み出し、合う順を決める。
- 開いただけのページ(ADR-0024)は、候補にしない。

### 画面

- 見出しの横に、**名前でページを探す欄**を置く。どのページからでも探せる。
- 入力が止まってから 0.15 秒後に探し、候補を欄の下に出す。いちばん合う候補を、選んだ状態にする。
- 上下の矢印キーで候補を選び、Enter で開く。候補を押しても開く。Esc で候補を閉じる。
- 何も入力していないときは、最近更新したページを候補にする。合う名前がなければ、そのことを伝える。
- ページのAPIが無効な環境(公開環境。ADR-0009)では、欄を出さない。

## 理由(ユーザーストーリーから)

- **US-10**「タイトルは、入力するたびに候補が絞り込まれる(あいまいな一致を含む)」に対応する。
- 日本語の名前は、単語の区切りがなく、送り仮名や助詞を省いて思い出すことが多い。文字が順に出てくれば合うようにすると、「買物」「打合せ」のような入力で見つかる。

## 検討した他の案

| 案                                                       | 採用しなかった理由                                                                                        |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| すべてのページの名前を画面に読み込み、画面の中で絞り込む | ページが増えると、開くたびに読み込む量が増える。合わせ方は純粋な関数なので、必要になれば画面でも使える    |
| 前方一致だけにする                                       | 名前の先頭を覚えていないと見つからない                                                                    |
| 編集距離(打ちまちがいを許す)で合わせる                   | 名前が短い日本語では、関係のない名前が多く合ってしまう。候補を SQL で絞れず、すべての名前を読むことになる |
| 全文検索の索引(FTS5)で、名前も探す                       | 本文の検索(このあとの変更)とは、求める結果が違う。名前は、途中まで打った文字で絞り込めることが大事        |
| 候補を、リンクにして並べる(コンボボックスにしない)       | 矢印キーと Enter で選べない。入力しながら選ぶ操作には、コンボボックスの作法が合う                         |

## わかっている制約

- 全角と半角の違い(「ＡＢＣ」と「ABC」)、ひらがなとカタカナの違い、漢字の読みでは、合わない。
- 文字が飛び飛びに合う候補は、短い入力(1〜2文字)では多くなる。先頭や途中に合うものを先に並べることで、埋もれないようにしている。
- 合う名前が1,000件を超えると、更新が古いものは、合う順を決める対象にならない。
- 候補に出るのは、台帳に反映されたページである(書き換えが落ち着いてから約2秒後。ADR-0024)。作ったばかりのページや、変えたばかりの名前は、すぐには出ない。
- 入力のたびに、台帳の名前をすべて調べる。ページが非常に多いプロジェクトでは、遅くなる。
- Enter は、選んでいる候補を開く。入力した名前そのもののページを作るには、トップの「新しいページの名前」を使う。
